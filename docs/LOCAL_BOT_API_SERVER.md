# Свой Bot API server: как снять потолок в 20 МБ

Код к этому готов. Здесь записано, что осталось сделать руками, чего это
стоит и чем опасно — потому что шаг необратим в одну сторону и затрагивает
всех ботов сразу.

## Зачем

Облачный Bot API отказывает `getFile` на файлах больше **20 МБ**. Мини-апп при
этом принимает 100 МБ. Человек отправляет в чат сорокамегабайтное видео и
получает отказ; тот же файл в приложении загружается. Свой сервер отдаёт до
**2000 МБ** и убирает этот перекос.

## Чего это стоит и чем опасно

**Шаг необратим в одну сторону.** Бот, вызвавший `logOut` на облачном API,
работает **только** через локальный сервер. Отката «на лету» нет: вернуться
можно, вызвав `close` уже на локальном сервере и подождав, но пока он лежит —
бот молчит. Облако как запасной путь недоступно.

**Переходят все боты сразу.** Платформа многоботовая; `logOut` делается на
каждый токен отдельно, и любой пропущенный токен остаётся в облаке.

**Локальный сервер становится частью критического пути.** Его падение — это
молчание всех ботов, а не деградация. Нужен перезапуск, диск под файлы и
присмотр.

## Что уже сделано в коде

Ровно одно место знает адрес API — `src/services/telegramApi.ts` и его копия
для render-приложения `apps/vibee-editor/render/src/telegram-api.ts`. Обе
читают одну переменную:

| переменная          | не задана                                 | задана                           |
| ------------------- | ----------------------------------------- | -------------------------------- |
| `TELEGRAM_API_ROOT` | `https://api.telegram.org`, потолок 20 МБ | указанный адрес, потолок 2000 МБ |

Потолок **выводится** из неё, а не записан отдельно, поэтому отказ не может
назвать предел, который никто не применяет. Битое значение роняет процесс на
старте с указанием переменной — молчаливый откат в облако выглядел бы
исправным во всех логах и убил бы всех ботов после `logOut`.

Перепись `src/__tests__/telegramApiRootCensus.test.ts` держит инвариант: ни
одного зашитого адреса и ни одного бота без настроенного корня. Строки, где
адрес нужен по делу (разбор, вычистка токена из логов, пояснение), помечены
`telegram-api-root-ok` — каждое исключение записано, а не забыто.

## Порядок действий

1. **Ключи приложения.** Получить `api_id` и `api_hash` на
   [my.telegram.org](https://my.telegram.org) → API development tools.

2. **Поднять сервис.** Образ `aiogram/telegram-bot-api` (или сборка
   `tdlib/telegram-bot-api`). Нужен постоянный диск под `--dir`: сервер хранит
   файлы на нём, и без диска они пропадут при перезапуске.

   ```
   TELEGRAM_API_ID=<из шага 1>
   TELEGRAM_API_HASH=<из шага 1>
   ```

   Внутренний адрес в Railway — вида `http://bot-api.railway.internal:8081`.
   Наружу его выставлять не нужно и не следует: в путях запросов идут токены
   ботов.

3. **Проверить сервер до перехода.** Пока ни один бот не разлогинен, облако
   ещё работает — это единственный безопасный момент. Убедиться, что сервис
   отвечает и что диск примонтирован.

4. **`logOut` на каждый токен.** Для каждого бота:

   ```bash
   curl -s "https://api.telegram.org/bot<TOKEN>/logOut"
   ```

   После этого бот доступен только через локальный сервер. Список токенов —
   переменные `BOT_TOKEN_*` в Railway.

5. **Задать переменную и перезапустить.**

   ```bash
   railway variables --set TELEGRAM_API_ROOT=http://bot-api.railway.internal:8081
   ```

6. **Проверить.** Отправить боту файл больше 20 МБ. До перехода приходит отказ
   с названием предела; после — файл проходит. Отказ и предел берутся из одной
   функции, так что расходиться они не могут.

## Если нужно вернуться

Вызвать `close` на **локальном** сервере для каждого бота, дождаться ответа,
снять `TELEGRAM_API_ROOT` и перезапустить. Пока это не сделано, снятие одной
переменной вернёт код в облако, где боты разлогинены, — то есть в тишину.
Именно поэтому переменная и `logOut` меняются в одном окне, а не по отдельности.
