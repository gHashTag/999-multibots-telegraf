# Сколько не видят мои же инструменты

Вчерашняя находка: осмотр репозитория на секреты видел на 50 файлов меньше, чем
думал. Молчаливая слепота инструмента дороже ненайденного дефекта — она
обесценивает ВСЕ выводы, сделанные этим инструментом.

Проверил все обходы файлов тем же вопросом. Замер:
`scripts/probe-tool-blindness.cjs`.

## Знаменатели

```
файлов на диске (без node_modules и .git): 3206

git ls-files      : 2854 имён, НЕ открывается 50
git ls-files -z   : 2854 имён, НЕ открывается  0

файлов с не-ASCII именами на диске: 57
из них .ts:                           0
```

Пятьдесят выпавших — все в `data/reports/` (отчёты с русскими именами). Кода
среди них нет, но осмотр секретов ходил именно по этому списку.

## Что проверено и оказалось чистым

**Обходы каталога `src`** экранирование не задевает: они ходят через
`readdirSync`, а не через git. Проверено отдельно — файлов `.ts` с не-ASCII
именами ноль.

**Нечитаемых файлов нет:** из 886 файлов `.ts` не читается ноль, двоичных ноль,
больше 2 МБ ноль. То есть повсеместный `catch { continue }` сейчас ничего не
прячет — но и не скажет, если начнёт.

**Расширений мимо осмотра нет:** `.tsx`, `.mts`, `.cts`, `.jsx` в `src` — ноль.
Все искалки берут `.ts`, и этого достаточно.

## Что исправлено

**`git ls-files` без `-z`** — оставался в двух местах, оба исправлены вчера и
сегодня закреплены тестом: `src/__tests__/tools/no-silent-blindness.test.ts` не
даёт появиться новому.

**Пропуск без счётчика** в разборе маршрутов. Стояло:

```ts
const file = routeFileFor(rel)
if (!fs.existsSync(file)) continue
```

Три раза. Если бы `routeFileFor` перестал разрешать пути, ВСЕ роутеры
отбрасывались бы, и весь разбор проходил бы зелёным, ничего не осмотрев.
Теперь пропуски копятся в счётчик, и отдельная проверка требует, чтобы он был
пуст.

**Пустой цикл** в разборе событий: перебирались два возможных файла клиента
Inngest, и если бы оба переехали, проверка прошла бы, ничего не проверив.
Теперь считается, сколько файлов открыто, и ноль роняет проверку.

## Ложное срабатывание собственного детектора

Детектор пометил `callback-protection.test.ts` как «пропуск несуществующего без
счётчика». Прочитал — там наоборот: отсутствие файла попадает в список
нарушений (`missing.push('файла нет')`). Шаблон срабатывал на форму, а не на
смысл.

Второй раз за неделю мой детектор врёт про мой же код. Правило прежнее:
находка инструмента — кандидат, а не факт.

## Что осталось как есть

`catch { continue }` в девяти инструментах. Сейчас он не прячет ничего
(нечитаемых файлов ноль), а переписывать девять обходов ради формы — работа
без пользы. Тест выше следит за условием, при котором это станет опасно:
появится хоть один нечитаемый `.ts` — проверка упадёт и назовёт его.
