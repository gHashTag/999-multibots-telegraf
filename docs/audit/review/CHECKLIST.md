# Чек-лист разбора Inngest-функции (2026-09-13)

Для каждой функции читать файл целиком (см. `file` в `/tmp/fn_list.json`), а также
вызываемые хелперы, если от них зависит вердикт. Только чтение кода — ничего не менять.

Для каждой функции зафиксировать (с `путь:строка`):

1. **Durability.** Побочные эффекты (сеть, БД, Telegram, списания) вне `step.run` — есть? Код между
   шагами повторяется при replay: что там делается? Недетерминизм вне шагов (`Date.now`, `Math.random`,
   чтение env, которые влияют на ветвление)?
2. **Step IDs.** Уникальны и стабильны? Динамические (`step-${i}`) — по стабильному ключу или по индексу
   массива (перестановка ломает memoization)? Дубликаты ID?
3. **Размер результата шага.** Что возвращает каждый `step.run` — большие буферы/base64/массивы?
   (результат сериализуется и хранится у Inngest).
4. **Ошибки.** `NonRetriableError` для валидации/бизнес-отказов vs обычный throw (лишние retry)?
   `RetryAfterError` для 429/лимитов провайдера? `retries` в конфиге оправдан? Что делает `onFailure`?
5. **Деньги.** Порядок: списание → платный API → доставка. Что при падении после списания — возврат?
   Двойное списание при retry шага? Идемпотентность платежа (ключ операции)?
6. **Flow control.** Есть ли `concurrency` (ключ по пользователю/боту), `rateLimit`/`throttle`,
   `debounce`, `idempotency` в конфиге функции? Нужны ли — по характеру функции (платные API,
   рассылки, cron)?
7. **Ожидания.** Поллинг внешнего статуса циклом/`setTimeout` вместо `step.sleep` /
   `step.waitForEvent` / `step.sleepUntil`? Таймаут ожидания есть?
8. **Fan-out / invoke.** Отправка событий через `step.sendEvent` (durable) или `inngest.send` внутри
   шага/вне шага? `step.invoke` где нужен результат?
9. **Cancel / timeouts.** `cancelOn`, `timeouts.start/finish` — нужны ли?
10. **Схема события.** Валидация payload (zod) на входе; тип события зарегистрирован в схемах клиента?
11. **Safe mode.** Все платные/исходящие шаги закрыты `isSafeMode`? Что проба не покрывает?
12. **Observability.** Логи структурные, содержат `runId`/`telegram_id`/`bot_name`? Метрики?
13. **Тесты.** Есть ли unit-тест функции (`src/__tests__/inngest/`)? Что он покрывает?
14. **Дубли и мёртвый код** внутри файла; расхождения с манифестом (`steps`, `side_effects`).

Формат вывода на функцию:

```
## <id> — <file>
Назначение (1–2 строки, из кода).
Сильное: …
Слабое (P0 = деньги/потеря данных/двойной эффект; P1 = надёжность/retry/flow control; P2 = гигиена):
- [P0] … (`file:line`)
Предложение: конкретное изменение (что и где), 1–3 пункта.
Не проверено: …
```

В конце файла — сводная таблица: id | P0 | P1 | P2 | главное предложение.
Прозa по-русски, идентификаторы кода по-английски. Не утверждать о поведении в проде — только о коде.
