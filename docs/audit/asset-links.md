## Что чинит эта итерация

### 1. Зеркалирование переведено на Supabase Storage

Прежний код зеркалировал в S3 и **всегда падал в откат**: регион в переменных
не совпадал с endpoint, а после исправления региона приходил `Access Denied`.
Эти доступы выдаёт владелец, и ожидание означало терять файлы дальше.

**Supabase Storage работает уже сейчас** — теми же ключами, что есть у бота.
Проверено сквозным прогоном:

```
источник fal            → скачано 3 302 608 байт
загрузка в images       → 200
чтение зеркала          → 200, content-length 3 302 608
размер совпал           → зеркало полноценное
уборка пробного файла   → 200
```

Новых учётных данных не нужно.

### 2. Закрыта вторая дверь

`videoGenerator/helpers/supabaseHelper.ts` вставлял в `assets` **напрямую**,
минуя зеркалирование. То есть правка в одном месте эту дорогу не закрывала:
видео из `videoGenerator` продолжали сохраняться ссылкой провайдера.

Теперь делегирует общему пути. Не копирует зеркалирование, а именно
делегирует: две копии логики разъезжаются, и разъезжаются молча — ровно так и
вышло в прошлый раз.

### 3. Регрессия закрыта тестом

`src/__tests__/assets/no-direct-insert.test.ts` — три проверки: разбор
что-то находит, нет прямых вставок вне разрешённого списка, в списке нет
файлов, которые больше не вставляют.

Проверено, что тест не декоративный: при возврате прямой вставки он падает и
называет файл со строкой.
