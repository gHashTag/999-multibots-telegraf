# СРОЧНО: токены ботов лежат в базе открытым текстом

## Что найдено

В колонке `users.photo_url` — **264 строки** с адресами вида

```
https://api.telegram.org/file/bot<ТОКЕН>/<путь к файлу>
```

Разных токенов — **14** (по десяти идентификаторам ботов). Проверкой `getMe`
подтверждено: **шесть из них действующие** на момент замера.

| бот | токен |
|---|---|
| `@Gaia_Kamskaia_bot` | **действующий** |
| `@MetaMuse_Manifest_bot` | **действующий** |
| `@NeuroLenaAssistant_bot` | **действующий** |

Токен бота даёт полное управление: читать все входящие сообщения, писать от его
имени, менять настройки, забирать файлы.

## Насколько это было доступно

Отдельная неприятность: в одной из ранних итераций у роли `anon` был широкий
доступ к таблицам (исправлено тогда же). То есть эти токены какое-то время были
читаемы всяким, у кого есть публичный ключ.

## Откуда взялось

`middlewares/getUserPhotoUrl.ts` возвращала адрес файла Telegram **как есть**:

```ts
const photoUrl = `https://api.telegram.org/file/bot${ctx.telegram.token}/${file.file_path}`
return photoUrl
```

Дальше `createUserScene` клала это значение в `users.photo_url`.

Вдобавок такая ссылка живёт около часа — то есть **хранилась мёртвой почти
сразу после записи**. Проверено: из пяти случайных ни одна не работает.

## Что сделано в коде

`getUserPhotoUrl` перекладывает файл в собственное хранилище и возвращает
**свой** адрес. Если переложить не удалось — возвращает `null`, а не адрес с
токеном.

Регрессия закрыта `src/__tests__/security/no-token-in-urls.test.ts`:

1. разбор находит места, где такой адрес строится (страховка от самого себя);
2. такой адрес не возвращается из функции — в том числе через переменную;
3. такой адрес не кладётся в поля профиля.

Проверено мутацией: при возврате прежнего значения тест падает и называет
строку.

## Что нужно от вас — по порядку

1. **Перевыпустить токены шести ботов** у `@BotFather`. Это главное; всё
   остальное — уборка. Токены уже утекли, и код их больше не пишет, но
   утёкшее остаётся утёкшим.
2. **Обновить токены в Infisical** после перевыпуска.
3. **Очистить базу** — скрипт готов:

```bash
node scripts/redact-tokens-in-photo-url.cjs           # сухой прогон
node scripts/redact-tokens-in-photo-url.cjs --apply   # запись
```

Скрипт ставит `photo_url = null` для этих 264 строк. **Информация не
теряется**: все адреса давно мертвы, проверено. Я его не запускал — это правка
264 строк в профилях, и она ваша.

## Почему я не запустил очистку сам

Настоящее лекарство — перевыпуск токенов, и он всё равно за вами. Пока токены
не перевыпущены, очистка базы не защищает: утечка уже произошла. После
перевыпуска старые токены становятся безвредны, и очистка — просто гигиена.

То есть очистка без ротации даёт ложное чувство закрытого вопроса. Порядок
важнее скорости.

## Урок

**Секрет попадает в базу не через поле «пароль», а через адрес.** Никто не
писал `INSERT INTO users (token)`. Токен приехал внутри ссылки на аватар — в
поле, которое выглядит совершенно безобидно.

Ищите секреты не по именам колонок, а по **содержимому**: любое поле, куда
попадает построенный нами адрес к чужому API, — кандидат.
