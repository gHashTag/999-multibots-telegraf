# Дерево, в котором файл не перечисляется

**Состояние на 4 сентября 2026 (it.139): причина НЕ НАЙДЕНА.** Здесь записано
то, что померено, и то, что опровергнуто, — чтобы следующий заход не начинал
с нуля и не повторял снятые гипотезы.

## Симптом

```
Error: Cannot find module '<дерево>/stream'
  imported from <ГЛАВНЫЙ чекаут>/node_modules/vite-node/dist/client.mjs
Serialized Error: { code: 'ERR_MODULE_NOT_FOUND', url: 'file:///<дерево>/stream' }
```

Импортёр живёт в главном чекауте (доступен через симлинк `node_modules`), а
**встроенный** модуль `stream` резолвится как путь **относительно дерева**.

## Что установлено

- Плоха **пара (дерево, файл)**, а не дерево целиком: в одном и том же дереве
  один файл не перечисляется 3 прогона из 3, соседний проходит 3 из 3.
- Детерминировано: повторные прогоны дают тот же ответ.
- На 4 сентября деградированы **2 дерева из 25**.

## Что ОПРОВЕРГНУТО (не проверять заново)

| гипотеза                           | как снята                                                                   |
| ---------------------------------- | --------------------------------------------------------------------------- |
| код / коммит                       | свежее дерево на **том же** коммите — здорово (проверено на обоих коммитах) |
| расположение                       | тот же коммит здоров и под `/tmp`, и под `/var/folders/.../T`               |
| неотслеживаемые файлы              | их **ноль**; верхний уровень совпадает с здоровым деревом                   |
| устарелость ветки                  | дерево на **75** коммитов позади здорово, на **27** — нет                   |
| `vitest.config.ts`, `package.json` | одинаковые во всех деревьях (сверено хешами)                                |
| общий кэш `node_modules/.vite`     | **удалён целиком** — симптом остался                                        |
| цепочка симлинков `node_modules`   | у деградированных ссылка ведёт прямо в главный чекаут                       |

Отдельно: кэш лежит в `node_modules/.vite/vitest/da39a3ee5e6b4b0d3255bfef95601890afd80709`,
и это SHA-1 **пустой строки** — то есть ключ кэша не различает деревья вовсе.
Само по себе это ничего не объясняет (удаление кэша не помогло), но структуру
стоит помнить.

## Чего делать НЕ надо

**Не пересоздавать дерево как «лечение».** Проверено: пересоздание на том же
пути и коммите симптом не снимает. Команда `wt-refresh` была написана и
**удалена** — лекарство, которое не лечит, хуже отсутствия лекарства.

## Что делать

`tri trust` перед тем, как верить вердикту гейта в дереве, и `tri trust-all`,
чтобы увидеть картину целиком. Если дерево деградировано — брать вердикт из
главного чекаута.

`tri trust` берёт **три** пробных файла. Пока проба была одна, команда звала
годными оба деградированных дерева: вопрос был уже названия, популяция —
один файл.

## Куда копать дальше

Разница между здоровым и больным деревом на одном коммите не найдена ни в
одном из проверенных мест. Следующий разумный шаг — сравнить не файлы, а
**поведение резолвера**: запустить vite-node с включённой трассировкой в обоих
деревьях и сличить, на каком шаге `stream` перестаёт считаться встроенным.
