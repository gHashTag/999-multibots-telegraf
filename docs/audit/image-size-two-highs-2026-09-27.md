# Две последние «high» от dependabot: image-size. Почему их нельзя закрыть сегодня

27.09.2026. После мержа #3137 осталось 5 открытых алертов из 27, и оба
оставшихся «high» — это один и тот же пакет `image-size` (алерты #677 и #678,
DoS в парсерах ICNS / JXL / HEIF, уязвимы `>= 0.6.3, <= 2.0.2`, исправлено
только в `2.0.3`).

Этот документ существует ровно для одного: чтобы следующий виток не начал
сочинять фикс заново. Ниже — не мнение, а измерения.

## Откуда он приходит

В `mobile/package-lock.json` стоит `image-size@1.2.1`, и хочет его **ровно
один** пакет:

```
WANTS node_modules/metro -> ^1.0.2
```

`metro` — это бандлер React Native, он же сборщик Expo-приложения. Он не
выкладывается ни в бота, ни в рендер: ни один рантайм-путь нашего сервера его не
импортирует. Dependabot помечает алерт как `runtime` потому, что пакет лежит в
`dependencies` манифеста, а не потому, что он исполняется в продакшне.

## Почему нельзя просто поднять версию

Патча в линии 1.x не существует — адвайзори даёт первую исправленную версию
`2.0.3`. Значит закрыть алерт можно только override'ом на `^2.0.3`, поверх
диапазона `^1.0.2`, который просит metro. Проверено, а не предположено:

```js
// metro 0.81.0, package/src/Assets.js:7
const getImageSize = require('image-size')
// ...вызывается как функция
```

```
$ npm i image-size@2.0.3 && node -e "const m=require('image-size');
    console.log('callable:', typeof m==='function'); console.log(Object.keys(m).join(','))"
callable: false
keys: disableTypes,imageSize,default,types
```

В v2 у CJS-сборки больше нет вызываемого экспорта по умолчанию. Override на
`2.0.3` не «поднимет версию» — он сломает бандлер мобильного приложения на
первом же ассете.

## Почему обновление Expo это тоже не решит

Это была рабочая гипотеза предыдущего витка («поднять Expo SDK, metro подтянет
image-size 2»). Гипотеза **неверна**:

```
metro 0.81.0 image-size: ^1.0.2
metro 0.82.0 image-size: ^1.0.2
metro 0.83.0 image-size: ^1.0.2
```

Наверху никто ещё не переехал. Обновление Expo SDK — полезная работа сама по
себе, но к этим двум алертам оно отношения не имеет.

## Что с этим делать

Ничего — до тех пор, пока не наступит одно из двух:

1. metro выпустит версию, которая просит `image-size@^2`. Тогда алерты закроются
   обычным обновлением Expo/metro, без override'ов.
2. Появится патч в линии 1.x. Тогда достаточно `overrides: { "image-size@1": "…" }`.

Проверять дешево: `npm view metro dependencies.image-size` и адвайзори по
`image-size`. Пока оба ответа те же, что выше, — правильное действие это
оставить алерты открытыми и не выдавать сломанный бандлер за закрытую
уязвимость.

Риск, который мы при этом принимаем, назван честно: отказ в обслуживании в
парсере картинок, доступный только через картинки, которые разработчик сам
кладёт в бандл мобильного приложения на своей машине. Это не путь, по которому
приходит недоверенный ввод.
