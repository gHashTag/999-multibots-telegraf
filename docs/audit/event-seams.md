# Швы событий Inngest: кто шлёт и кто слушает

Продолжение разбора после `docs/audit/route-seams.md`. Тот же вопрос, другой
класс: **имена событий**.

Замер: `scripts/probe-event-seams.cjs`. Регрессия закрыта
`src/__tests__/inngest/event-seams.test.ts`.

## Почему этот класс хуже, чем маршруты

Неверный адрес маршрута даёт 404 — след в логах есть. **Inngest принимает любое
событие** и просто не находит подписчика. Отправка успешна, ошибки нет, работа
не выполняется. Никакого следа, кроме отсутствия результата.

Поймать можно только сверкой двух списков: имена в `createFunction({event})`
против имён в `inngest.send({name})`.

## Что нашлось

### 1. Карта MCP-сервера: неверны были все девять строк

`mcp-server.ts` сопоставляет идентификатор функции с именем события. Ни одна
строка не совпадала с действительностью:

| в карте было | функция подписана на |
|---|---|
| `render/riddle` | `render-riddle` |
| `render/start` | `render` |
| `render/avatar` | `render/avatar-video` |
| `training/model.v2` | `model/training.v2.requested` |
| `training/morph` | `morph/images.requested` |
| `generation/neuro-image` | `neuro/photo.generate` |
| `payment/process` | `payment/process-ai-server` |
| `broadcast/message` | `broadcast/send-message` |
| `ai-reels/callback` | `ai-reels-callback` |

**MCP-сервер не мог запустить ни одну функцию из тех, что перечисляет**, и
сообщал об успехе. Исправлено.

### 2. `INNGEST_EVENTS`: 17 констант из 24 указывали в пустоту

Карта заведена «для типобезопасности». На деле 17 значений называли события, на
которые никто не подписан. Разработчик, поступивший правильно и взявший
константу вместо строки, отправлял бы в никуда — с большей уверенностью, чем
если бы написал строку руками.

Особенно показательно `RENDER_RIDDLE: 'render/riddle'`: настоящее имя —
`render-riddle`, **без слэша**. Живой путь работает только потому, что
`render-server-client.ts:147` шлёт строку напрямую, минуя константу.

Все значения приведены к реальным. Карта дублировалась в двух файлах
(`client.ts` и `inngestClient.ts`) с расхождениями — исправлены оба.

### 3. `instagram/scraper` против `instagram/scraper-v2`

Два места слали `instagram/scraper`; единственный подписчик объявлен как
`{ event: 'instagram/scraper-v2' }`. Исправлено в обоих.

### 4. Событие не отправлялось вовсе, а пользователю говорили «запущено»

Самое дорогое. В `generateInstagramScraping` отправка была закомментирована:

```js
// ВРЕМЕННО: inngest отключён
// const sendResult = await inngest.send(inngestEvent)
const sendResult = { ids: ['disabled'] }
...
logger.info('✅ [Instagram Scraper] Событие успешно отправлено в Inngest', …)
return { success: true, message: '🚀 Анализ конкурентов запущен! Результаты
будут готовы через несколько минут.' }
```

Функция лгала трижды: **в логе**, **в коде возврата** и **в тексте
пользователю**.

А вызывающие сцены списывали деньги **до** вызова и смотрели только на
`result.success`.

**Измерено:** 28 списаний `service_type='instagram_parser'` у трёх человек на
**94 звезды** при нуле запусков. Из них двое — настоящие люди (11 и 8 звёзд),
остальное — аккаунт владельца.

Хуже: ветка неудачи в `instagramParserWizard` писала «💰 Средства не были
списаны», хотя списание уже произошло строкой выше. Возврат делался только в
`catch`, то есть при исключении; `success: false` оставлял человека без услуги,
без денег и с сообщением, что деньги на месте.

### Что сделано

- сервис отказывает честно: `success: false` с причиной и текстом «средства не
  списаны»;
- **обе сцены переведены на порядок «сначала запуск, потом списание»** — это
  убирает целый класс таких случаев;
- возврат в `catch` теперь под флагом `charged`: после переноса списания
  безусловный возврат стал бы начислением из воздуха;
- имя события исправлено на `instagram/scraper-v2`, чтобы включение не
  воскресило вторую ошибку.

**Включить нельзя:** `RAPIDAPI_INSTAGRAM_KEY` в проде **не задана**, и функция
`instagramScraperV2` без неё всё равно упадёт. «Раскомментировать» — не
починка, а перенос отказа на шаг позже, уже после списания.

## Осталось незакрытым

События, которые шлют, но подписчика нет. Перечислены в списке исключений
теста — с причинами, чтобы молчание не выглядело как норма:

| событие | откуда | статус |
|---|---|---|
| `instagram/scrape-similar-users` | `instagramScraper-v2.ts:1821` | подписчик не заведён |
| `telegram/send-admin-notification` | `kieAiWebhookMonitor.ts:55` | уведомления админам теряются |
| `neuro/photo.failed` | `neuroImageGeneration.ts:458` | отказы генерации никто не обрабатывает |
| `render/execute` | `render/steps.ts:1475` | потребитель в отдельном рендер-сервере |
| `test/hello.world` | демо | подписчик не нужен |

## Проверка

`src/__tests__/inngest/event-seams.test.ts`, 5 проверок: подписчики вообще
находятся (страховка от самого себя), `INNGEST_EVENTS` ведёт на реальных
подписчиков, карта MCP ведёт на реальных подписчиков, в рабочем коде нет
отправок в пустоту, список исключений не пережил свою причину.

Проверено, что тест не декоративный: при возврате `renderRiddle: 'render/riddle'`
он падает.
