# Проверка лечения: будут ли новые поля заполняться

Четыре итерации подряд я чинил различимость — причина возврата, исход
генерации, признак записи видео, правда о возврате. Все правки построены на
предположении, что код исполняется.

В этом проекте предположение не бесплатное: 13 функций Inngest из 35 не
зарегистрированы, и три моих прошлых правки уже уезжали в такие файлы
(`unregistered-functions.md`). Правка в неисполняемом файле выглядит как работа
и не делает ничего — а обнаруживается через месяц, когда оказывается, что
копилась пустота.

Замер: `scripts/probe-will-it-write.cjs`.

## Результат: всё семь правок исполняются

| что чинил | зовут |
|---|---|
| причина возврата (`refundUser`) | 15 мест, включая `CancelButtonService` |
| правда о возврате (`refundAndTell`) | 4 визарда |
| исход генерации (`savePrompt`) | 14 сервисов |
| признак записи видео (`saveVideoUrlToSupabase`) | 5 мест |
| проверка признака (`saveVideoUrlHelper`) | `generateImageToVideo`, `generateTextToVideo` |
| награда за приглашение (`rewardInviter`) | `createUserScene` |
| промо: отказ закрытый (`processPromoLink`) | `createUserScene` |

Цепочка для видео прослежена целиком, до точки входа:

```
registerCommands → imageToVideoWizard → handleImageToVideoDirect
  → generateImageToVideo → saveVideoUrlHelper → saveVideoUrlToSupabase
```

База новые значения примет: `prompts_history.status` уже содержит `success`,
`payments_v2.metadata` — jsonb. Строк с `metadata.refund_reason` пока ноль, что
и ожидается: правка выкачена час назад, а трафика почти нет.

## Ошибка метода, которую пришлось исправить дважды

**Первая версия** проверяла достижимость файла по импортам от точек входа. Она
выдала «⚠️ достижим только через файл-бочку» для четырёх правок из семи — и это
ничего не значило: импорт через `@/services` законен.

**Вторая версия** проверяла, зовёт ли кто-нибудь хоть одно имя, экспортируемое
файлом. Мутация её убила: `supabaseHelper.ts` экспортирует несколько функций, и
переименование нужной оставляло проверку зелёной — её удовлетворял соседний
экспорт.

**Третья версия** проверяет конкретный символ. Мутация ловит.

Это третий раз за неделю, когда мой собственный инструмент оказывается неверным
раньше, чем код, который он проверяет.

## Найдено попутно: 472 строки мёртвого кода, которые я на этой неделе правил

`src/inngest_app/functions/neuroImageGeneration.ts` не импортируется никем,
кроме тестов. Зарегистрирована другая копия —
`functions/generation/neuroImageGeneration`. Файлы разошлись на 244 строки, то
есть это не свежий дубль, а отдельная ветка.

Я сам добавил в него параметр `outcome` два дня назад, не заметив, что файл
мёртв. Компилятор был доволен: файл компилируется и импортируется тестом.

Список `DELIBERATELY_UNREGISTERED` в `registration.test.ts` этот файл уже
содержал — то есть система, построенная в PR #515, знала. Не знал я, потому что
правил файл, а не читал тест. Поэтому пометка теперь стоит в самом файле: её
увидит тот, кто его откроет.

## Что закреплено тестом

`src/__tests__/observability/writers-have-callers.test.ts`, 13 проверок:

- каждый писатель действительно экспортирует заявленный символ (страховка от
  опечатки в списке);
- метка правки на месте — правку не откатили;
- этот символ кто-то зовёт — правка исполняется.

Проверено мутацией: переименование `saveVideoUrlHelper` у вызывающих роняет
ровно одну проверку и называет её.
