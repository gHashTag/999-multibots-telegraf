## 5. Implications for a day-zero ledger reset

**Two ledgers, no bridge.** The render's user_tokens/star_payments/token_invoices (Postgres) and the bot's payments_v2 (Supabase) are written only by their own owner: the render never writes Supabase (its only payments_v2 access is a SELECT, crm-tools.ts:208; comment render-server.ts:11131-11135), and the bot writes to the render only through /api/stars/credit and /api/star-paid. user_tokens is a running balance column, not a ledger (tools.ts:255-259); star_payments is an idempotency lock keyed on charge_id whose `amount` is tokens, not stars; hive_events is a fire-and-forget journal. So "Σ rows = balance" does not hold on the render side by construction, and no join key exists between star_payments and token_invoices.

**Writers that must honour an archive marker (anything that INSERTs into payments_v2).** Four shared writers plus raw inserts:

1. `setPayments` / `buildPaymentRow` — src/core/supabase/setPayments.ts:111 (Stars, Robokassa, x402; passes neither category nor is_test).
2. `updateUserBalanceUnlocked` — src/core/supabase/updateUserBalance.ts:504 (every charge, most refunds, /addbalance, marketplace; category default REAL :525).
3. `directPaymentProcessorUnlocked` — src/core/supabase/directPayment.ts:155 (neuro-photo, image-to-prompt, promo, referral, adminRenew).
4. `createSuccessfulPayment` — src/core/supabase/createSuccessfulPayment.ts:196 (/admin_sub override only).
5. Raw inserts bypassing all four: tonPaymentScene/index.ts:147, tonNativePaymentScene/index.ts:151, groupMemberHandler.ts:112 (dormant), scripts/users/grant-bonus-stars-435572800.js:129, and the unapplied deduct_balance RPC (:71).
   No writer in src sets `is_test` today; category is set by only some callers. A marker column would have to be added in all five places above.

**Writers that UPDATE pre-existing rows by inv_id and could complete an archived row after reset:** robokassa.routes.ts:198 CAS (lookup requires status=PENDING, payments.ts:15-18 — a late callback for one of the ~164 pre-reset PENDING Robokassa rows would complete it), updateUserBalance.ts:451 inv_id branch (no status filter, returns true on 0 rows), payments.ts:67 updatePaymentStatus (x402 only), the TON CAS updates, Inngest processPayment (:160, inactive).
