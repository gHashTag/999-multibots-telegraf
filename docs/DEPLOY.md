# 🚀 Автоматическое развертывание в продакшн

## Быстрый запуск

```bash
npm run deploy
```

или

```bash
./scripts/deploy.sh
```

## Что делает команда deploy

Команда `deploy` выполняет **полный автоматический цикл развертывания** изменений TypeScript/JavaScript в продакшн:

### 📋 Этапы развертывания:

1. **Проверка окружения** - проверяет что запущена из корня проекта
2. **Создание коммита** - автоматически коммитит все изменения (с опциональным сообщением)
3. **Отправка в репозиторий** - пушит изменения в `production` branch
4. **Подключение к серверу** - подключается к продакшн серверу `212.86.115.30`
5. **Обновление кода** - выполняет `git pull origin production`
6. **Остановка контейнера** - останавливает старый Docker контейнер `999-multibots`
7. **Удаление контейнера** - удаляет старый контейнер
8. **🔥 ПРИНУДИТЕЛЬНАЯ ПЕРЕСБОРКА** - собирает Docker БЕЗ кеша (`--no-cache`)
9. **Запуск нового контейнера** - запускает обновленный контейнер
10. **Проверка развертывания** - проверяет статус и логи

## 🚨 КРИТИЧЕСКИ ВАЖНЫЕ ПРАВИЛА

### Правило #1: ПРИНУДИТЕЛЬНАЯ ПЕРЕСБОРКА DOCKER
```bash
# ✅ ПРАВИЛЬНО (что делает команда deploy):
docker build --no-cache -t 999-multibots .

# ❌ НЕПРАВИЛЬНО (НЕ работает для изменений кода):
docker restart 999-multibots
docker build -t 999-multibots .  # без --no-cache
```

**Почему это важно:**
- Docker кеширует слои сборки
- При изменении TypeScript/JavaScript кода БЕЗ `--no-cache` старый код остается в контейнере
- Изменения НЕ попадают в продакшн

### Правило #2: ПОЛНАЯ ЗАМЕНА КОНТЕЙНЕРА
```bash
# ✅ ПРАВИЛЬНО:
docker stop 999-multibots
docker rm 999-multibots
docker build --no-cache -t 999-multibots .
docker run -d --name 999-multibots ...

# ❌ НЕПРАВИЛЬНО:
docker restart 999-multibots  # НЕ применит изменения кода!
```

### Правило #3: КОММИТ ПЕРЕД РАЗВЕРТЫВАНИЕМ
- Все изменения ДОЛЖНЫ быть закоммичены
- Изменения ДОЛЖНЫ быть в `production` branch
- Продакшн сервер берет код ТОЛЬКО из репозитория

## 🔍 Проверка результата

После выполнения команды вы увидите:
- ✅ Статус нового контейнера
- 📜 Логи запуска (последние 20 строк)
- 📋 Команды для дополнительной проверки

### Дополнительные команды для проверки:

```bash
# Просмотр логов
ssh -i ~/.ssh/zomro root@212.86.115.30 'docker logs 999-multibots --tail 50'

# Проверка статуса контейнера
ssh -i ~/.ssh/zomro root@212.86.115.30 'docker ps | grep 999-multibots'

# Проверка что новый код применился
ssh -i ~/.ssh/zomro root@212.86.115.30 'docker exec 999-multibots head -10 /app/dist/core/supabase/getActiveUserModelsByTypeForHaim.js'
```

## ⚠️ Когда НЕ использовать deploy

**НЕ используйте** `deploy` команду если:
- Изменения только в конфигурационных файлах (.env)
- Нет изменений в TypeScript/JavaScript коде
- Нужно только перезапустить сервисы

Для таких случаев используйте:
```bash
# Простой перезапуск без пересборки
ssh -i ~/.ssh/zomro root@212.86.115.30 'docker restart 999-multibots'
```

## 🛡️ Безопасность

- Скрипт останавливается при любой ошибке (`set -e`)
- Проверяет наличие `package.json` для запуска из правильной директории
- Использует SSH ключ для безопасного подключения к серверу
- Проверяет статус контейнера перед операциями

## 🕐 Время выполнения

Полный цикл развертывания занимает **~5-7 минут**:
- Пересборка Docker: ~3-4 минуты
- Запуск и проверка: ~1-2 минуты
- Остальные операции: ~1 минута

## 🚨 В случае проблем

Если развертывание прервалось:

1. **Проверьте статус контейнера:**
   ```bash
   ssh -i ~/.ssh/zomro root@212.86.115.30 'docker ps -a | grep 999-multibots'
   ```

2. **Запустите заново:**
   ```bash
   npm run deploy
   ```

3. **Ручное восстановление (если нужно):**
   ```bash
   ssh -i ~/.ssh/zomro root@212.86.115.30
   cd /root/999-agents-telegraf
   docker stop 999-multibots || true
   docker rm 999-multibots || true
   docker build --no-cache -t 999-multibots .
   docker run -d --name 999-multibots --restart=always -p 3001:3001 -v /root/999-agents-telegraf/.env:/app/.env:ro 999-multibots
   ```
