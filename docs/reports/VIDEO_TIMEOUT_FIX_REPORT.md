# ✅ ОТЧЕТ: Исправление таймаутов генерации видео

## Проблема (РЕШЕНА)

**Симптомы:**
- ❌ "SERVER DOWN ALERT" - пугал пользователя
- ❌ "Plan B polling timeout" через 10 секунд
- ✅ Видео приходило, но с лишними сообщениями об ошибках

**Пользователь:** 144022504 (админ фермы ботов)

## root Cause

1. **Таймауты слишком короткие:** 5 попыток × 2 сек = 10 секунд (для Veo 3 нужно 30-60+ сек)
2. **Лишние уведомления:** Админские сообщения отправлялись пользователю-админу
3. **Конфликт Plan A/B:** Webhook работает, но Plan B таймаутится и сбивает с толку

## ✅ ИСПРАВЛЕНИЯ

### 1. Увеличены таймауты Plan B

**Файл:** `/src/modules/videoGenerator/generateImageToVideo.ts:918`

**БЫЛО:**
```typescript
const maxPollingAttempts = 5 // 10 секунд
```

**СТАЛО:**
```typescript
const maxPollingAttempts = 60 // 2 минуты
```

**Результат:** Plan B теперь ждет до 2 минут вместо 10 секунд.

### 2. Убраны лишние уведомления

**Файл:** `/src/modules/videoGenerator/generateImageToVideo.ts:67`

**БЫЛО:**
```typescript
for (const adminId of adminIds) {
  await botResult.bot.telegram.sendMessage(adminId, ...)
}
```

**СТАЛО:**
```typescript
// Исключаем пользователя, который инициировал генерацию
const technicalAdmins = adminIds.filter(id => id !== telegram_id)
for (const adminId of technicalAdmins) {
  await botResult.bot.telegram.sendMessage(adminId, ...)
}
```

**Результат:** Пользователь 144022504 больше НЕ получает админские уведомления.

### 3. Улучшена логика таймаута

**Файл:** `/src/modules/videoGenerator/generateImageToVideo.ts:1303-1316`

**ДОБАВЛЕНО:**
```typescript
// ПРОВЕРЯЕМ: пришло ли видео через webhook (Plan A)?
const taskContext = videoTaskStore.getTask(taskId)
const hasVideoFromWebhook = taskContext?.videoUrl

if (hasVideoFromWebhook) {
  logger.info('[I2V BG] Video already received via webhook, skipping timeout message')
  // Видео уже пришло через webhook, НЕ отправляем сообщение о таймауте
  return
}
```

**Результат:** Если видео пришло через webhook, пользователь НЕ получает сообщение о таймауте.

## Результат
