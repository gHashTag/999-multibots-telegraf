# Один кошелёк: `user_tokens` живёт, `payments_v2` уходит в архив

**Решение владельца, 2026-09-20.** Дальше — один кошелёк. Второй замораживается
и хранится только для аудита.

|         | Живая система                     | Архив             |
| ------- | --------------------------------- | ----------------- |
| Таблица | `user_tokens` (+ `star_payments`) | `payments_v2`     |
| База    | Postgres рендера (`getPool()`)    | облачный Supabase |
| Единица | токен                             | звезда (`stars`)  |
| Продукт | цифровой клон, мини-апп           | боты 1..12        |

Курс переноса **1 звезда = 1 токен** — не выбран, а измерен:
`creditStarsPayment` (`apps/vibee-editor/render/src/stars-credit.ts`) кредитует
оплаченную звезду в `user_tokens.balance` один к одному.

## Почему выживает именно `user_tokens`

Не потому, что он больше — он меньше: 9 файлов против 222. А потому, что там
находится продукт, который продаётся: цифровой клон. `payments_v2` обслуживает
старую витрину ботов, чей прайс владелец признал устаревшим (см.
`digital-clone-real-price`).

## Что «архив» значит буквально

1. `payments_v2` становится **read-only**: новых строк не пишем, старые не
   трогаем. Леджер append-only, вся история остаётся проверяемой.
2. Баланс и списания идут только через `user_tokens`.
3. Отчётность и аудит продолжают читать `payments_v2` — это и есть смысл архива.

**Удалять `payments_v2` нельзя.** В нём лежит единственная запись о реальных
деньгах, которые люди заплатили; часть возвратов и споров ещё возможна.

## Перенос балансов

Правило владельца: реальные оплаты переносятся, админские начисления — нет.

    перенос = min(реально оплачено, текущий баланс)

Первый предел отсекает админские начисления. Второй не возвращает уже
потраченное; потраченное списывается сначала с начисленного, то есть в пользу
плательщика.

### ✅ ВЫПОЛНЕНО 2026-09-20

**94 человека, 212 939 токенов** зачислены в `user_tokens`. Из них @playom —
102 251 (владелец подтвердил перенос, несмотря на админский статус).

Состояние базы рендера: было 30 строк / 38 683 токена → стало **114 строк /
251 622 токена**. Арифметика сходится: 38 683 + 212 939 = 251 622.

Перенос **идемпотентен**: каждая запись помечена `star_payments.charge_id =
'carry-2026-09-20-<telegram_id>'`, а `charge_id` — первичный ключ. Повторный
запуск даёт `0 users, 0 tokens` (проверено). Это тот же замок, которым
`creditStarsPayment` защищается от повторной доставки платежа Telegram — не
изобретён заново, а переиспользован.

Каждый пользователь переносился **своей транзакцией**: строка дедупа и движение
баланса коммитятся вместе, поэтому сбой не мог оставить отметку о переносе без
самого переноса.

212 939, а не 212 955: дробные остатки округлены вниз (`user_tokens.balance` —
целочисленная колонка), разница 16 токенов на всех.

Не переносится: **968 068⭐** админских начислений (по правилу) и
**365 393⭐** корзины «прочее» (`System_Balance_Migration`, `System_Operation`
и подобное) — по ней решения ещё нет.

## Узкое место переключения

Записи в `payments_v2` сосредоточены в `src/core/supabase/`, а не размазаны по
всем 222 файлам, которые упоминают таблицу (остальное — тесты, отчёты,
аналитика). Переключать нужно здесь:

    updateUserBalance.ts      directPayment.ts        setPayments.ts
    createSuccessfulPayment.ts  payments.ts           refundUser.ts (src/price/helpers)
    getUserBalanceStats.ts    checkPaymentStatus.ts   getPaymentsInfoByTelegramId.ts
    getTelegramIdFromInvId.ts  sendPaymentInfo.ts     createUser.ts
    getUserDetailsSubscription.ts

Чтение баланса идёт через RPC `get_user_balance`, **тело которого существует
только внутри Supabase** — в репозитории его нет. Это отдельный риск: логику
придётся воспроизвести на стороне `user_tokens`, а не перенести.

## Чего нельзя сделать одним движением

Заморозка `payments_v2` без перевода списаний **ломает 13 живых ботов** —
они сегодня берут деньги только оттуда. Порядок обязателен:

1. ✅ **касса включена** — `TOKENS_PAYMENT_BOT_TOKEN` задан на `vibee-render`
   (проверено 2026-09-20, длина значения 46). Кассиром работает `t27ai_bot`
   = BOT_TOKEN_12: он отвечает только на `pre_checkout_query` и
   `successful_payment`. Более ранний вывод «касса выключена» устарел;
2. ✅ **балансы перенесены** — см. раздел выше;
3. ⬜ перевести перечисленные файлы `src/core/supabase/` на `user_tokens`;
4. ⬜ только после этого закрыть `payments_v2` на запись.

Шаги 3 и 4 — единственное, что ещё удерживает старый кошелёк живым.
