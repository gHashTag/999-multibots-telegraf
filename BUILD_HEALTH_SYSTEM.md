# 🛡️ Система Раннего Предупреждения о Проблемах Билда

Этот документ описывает систему, которая позволяет узнать о проблемах билда **ДО** того, как они попадут в продакшн.

## 🎯 Цель

Предотвратить ситуации типа "сломался билд, не работает" путем раннего обнаружения проблем.

## 🔧 Доступные Команды

### Ежедневная разработка

```bash
# ⚡ Быстрая проверка (30 сек)
npm run check:quick

# 🔍 Полная проверка (2-3 мин)  
npm run check:build

# 🛡️ Проверка перед merge
npm run check:merge cicd
```

### Прямые вызовы скриптов

```bash
# Быстрая проверка
./scripts/quick-build-check.sh

# Полная диагностика
./scripts/check-build-health.sh

# Тест merge с другой веткой
./scripts/pre-merge-check.sh main
```

## 🤖 Автоматические Проверки

### Pre-commit хук
- Автоматически запускается перед каждым `git commit`
- Проверяет билд если есть изменения в `.ts/.js` файлах
- Блокирует коммит если билд сломан

```bash
# Пропустить проверку (аварийный случай)
git commit --no-verify -m "fix: urgent hotfix"
```

## 📊 Что Проверяется

### ⚡ Быстрая проверка (`check:quick`)
- ✅ TypeScript билд (`npm run build:nocheck`)
- ✅ Синтаксис основных файлов
- ⏱️ Время: ~30 секунд

### 🔍 Полная проверка (`check:build`)
- ✅ TypeScript билд
- ⚠️ Проверка типов (`npm run typecheck`)
- ⚠️ Линтер (`npm run lint`)
- ⚠️ Тесты (`npm test`)
- ⚠️ Аудит безопасности (`npm audit`)
- 📏 Размер билда
- ⏱️ Время: ~2-3 минуты

### 🛡️ Pre-merge проверка (`check:merge`)
- ✅ Проверка merge конфликтов
- ✅ Тестовое слияние в временной ветке
- ✅ Билд после merge
- ✅ Автоматическая очистка
- ⏱️ Время: ~1-2 минуты

## 🚨 Что Делать При Ошибках

### ❌ Билд сломан
```bash
# 1. Запустить детальную диагностику
npm run check:build

# 2. Исправить показанные ошибки

# 3. Проверить снова
npm run check:quick
```

### ⚠️ Предупреждения (не блокируют)
- Типы TypeScript
- Ошибки линтера  
- Провальные тесты
- Уязвимости зависимостей

## 📝 Примеры Использования

### Перед коммитом
```bash
# Проверить, что все ОК
npm run check:quick

# Если все хорошо - коммитить
git add .
git commit -m "feat: новая функциональность"
```

### Перед merge в продакшн
```bash
# Проверить совместимость с cicd
npm run check:merge cicd

# Если все ОК - создать PR
gh pr create --base cicd --title "..."
```

### При подозрении на поломку
```bash
# Полная диагностика
npm run check:build

# Проверить конкретную ошибку
npm run build:nocheck
```

## 🎯 Интеграция в Workflow

### В CI/CD пайплайне
```yaml
- name: Build Health Check  
  run: npm run check:build
```

### В pre-push хуке
```bash
#!/bin/sh
echo "Проверка перед push..."
npm run check:quick
```

## 💡 Советы

1. **Запускайте `npm run check:quick` часто** - это быстро
2. **Используйте `npm run check:build` перед важными PR**
3. **Всегда запускайте `npm run check:merge` перед merge в продакшн**
4. **При сомнениях - лучше перепроверить**

## 🔧 Настройка

Все скрипты находятся в `scripts/`:
- `check-build-health.sh` - полная проверка
- `quick-build-check.sh` - быстрая проверка  
- `pre-merge-check.sh` - проверка merge

Хуки в `.husky/`:
- `pre-commit-build-check` - автоматическая проверка

## 📞 Поддержка

При проблемах с системой проверки билда:
1. Проверьте права исполнения: `chmod +x scripts/*.sh`
2. Убедитесь что Node.js и npm работают
3. Попробуйте ручной билд: `npm run build:nocheck`
