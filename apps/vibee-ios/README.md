# Trinity S³AI — нативная оболочка для iOS

Нативный SwiftUI-контейнер поверх существующего мини-аппа. Задача была
«максимум нативного UI без большой переделки», поэтому переписаны экраны,
куда заходят КАЖДЫЙ раз, а те, куда заходят раз за сессию, остались вебом.

## Что нативное

| Экран | Чем сделан | Почему так |
| --- | --- | --- |
| Лента | SwiftUI + `AVPlayerLayer` | Вертикальный пейджинг, инерция и отскок от системы; `resizeAspectFill` даёт кадр во весь экран без полей |
| Агент | SwiftUI, потоковый NDJSON | Чат — самая частая точка входа |
| Профиль | SwiftUI | Простой список, переписывается за час |
| Редактор, ИИ | `WKWebView` | Холст, таймлайн и перетаскивание слоёв — месяцы работы на SwiftUI ради экрана, куда заходят раз за сессию |

## Сборка

На этой машине Xcode несёт SDK iOS 26.5, а из рантаймов установлен только
18.4. Из-за этого `xcodebuild` **не предлагает ни одного симуляторного
назначения** — в списке только устройства с «iOS 26.5 is not installed».
Поэтому собираем цель напрямую, минуя разрешение назначений:

```bash
xcodegen generate
xcodebuild -project Vibee.xcodeproj -target Vibee \
  -sdk iphonesimulator26.5 -configuration Debug -arch arm64 \
  SYMROOT=$PWD/build2 build

xcrun simctl install booted build2/Debug-iphonesimulator/Vibee.app
xcrun simctl launch booted ai.t27.vibee
```

## Одна полоса вкладок, а не две

Внутри `WKWebView` живёт собственная нижняя панель мини-аппа, и вместе с
нативной их видно ДВЕ. Прячем вебовую — на стороне контейнера, без
перевыпуска мини-аппа: тот же адрес открывается внутри Telegram, где эта
панель единственная и нужная.

Ищем панели **по геометрии**, а не по именам классов: приклеена к низу
(`fixed`/`sticky`), невысокая, во всю ширину. Перечисление селекторов уже
проиграло — на ленте поймало, в редакторе пропустило: там другие классы.

## Чего здесь нет

Полного нативного повторения редактора и генерации. Это не оболочка, а
переписывание продукта: холст со слоями, таймлайн с перетаскиванием,
предпросмотр рендера. Порядок, в котором это имеет смысл делать, — по
частоте входов, а не по списку экранов.

## Разрешения: их здесь нет, и это проверено

`NSCameraUsageDescription`, `NSMicrophoneUsageDescription`,
`NSPhotoLibraryUsageDescription` в Info.plist **отсутствуют намеренно**.
Приложение не обращается ни к камере, ни к микрофону, ни к галерее — поиск
по `Vibee/*.swift` не находит `AVCapture`, `PHPicker`, `UIImagePicker` и
`AVAudioRecorder`. Единственное упоминание звука — `AVAudioSession` с
категорией `.playback` в ленте, то есть ВОСПРОИЗВЕДЕНИЕ; разрешения оно не
требует.

Не добавляйте эти ключи «на всякий случай». Описание доступа, которым
приложение не пользуется, — самостоятельная причина отказа при проверке:
Apple спрашивает, где в приложении эта возможность, и ответа нет.

## Иконка приложения — её НЕТ

Картинки нет, и на домашнем экране приложение показывает пустой
квадрат-сетку (проверено на симуляторе). Загрузку это остановит:
App Store Connect отвергает сборку без иконки (ITMS-90022).

Нужен **исходник от владельца** — квадратный PNG 1024×1024, без
прозрачности и без скруглённых углов (систему скруглит сама). Заглушку
рисовать не стали: иконка — это лицо продукта, и временная картинка имеет
свойство доезжать до магазина.

Место под неё готово, класть один файл и ничего не настраивать:

```
Vibee/Assets.xcassets/AppIcon.appiconset/AppIcon.png
```

Одного файла 1024×1024 достаточно — остальные размеры Xcode делает сам
(single-size app icon, начиная с Xcode 14).

Пока файла нет, каждая сборка печатает `warning: The file "AppIcon.png" for
the image set "AppIcon" does not exist.` — это намеренно. Пустой набор
ничего не кладёт в бандл и ничего не пишет в Info.plist (проверено: в
собранном `.app` нет ни `Assets.car`, ни ключей `CFBundleIcons`), так что
предупреждение — единственный его след и единственная задача.

### ⚠️ На ЭТОЙ машине иконку сначала собрать нечем

Прочитайте до того, как положите PNG, иначе решите, что сломали сборку.

Пока каталог пуст, всё зелёное. Стоит положить настоящую иконку — падают
**обе** сборки, и симуляторная, и устройственная:

```
Vibee/Assets.xcassets: error: No simulator runtime version from ["22E238"]
available to use with iphonesimulator SDK version 23F81a
```

Проект тут ни при чём: тот же `actool`, запущенный руками мимо xcodebuild,
падает точно так же, и `ENABLE_ONLY_ACTIVE_RESOURCES=NO` не помогает. Xcode
26.6 несёт SDK 26.5, а из симуляторных рантаймов установлен только 18.4
(22E238), и `actool` отказывается компилировать любой каталог ресурсов.

Лечится докачкой рантайма, а не правкой проекта:

```bash
xcodebuild -downloadPlatform iOS      # несколько гигабайт
```

`fastlane preflight` проверяет это отдельно и называет ровно эту команду —
но только когда иконка уже лежит на месте: без неё каталог пуст и
компилировать нечего.

## Выкладка в TestFlight

```bash
cd apps/vibee-ios
fastlane preflight     # проверить готовность, ничего не собирая (~13 с)
fastlane build_only    # только .ipa, без отправки
fastlane beta          # собрать и отправить — СПРОСИТ ПОДТВЕРЖДЕНИЕ
fastlane bump          # показать следующий номер сборки, ничего не меняя
```

### `beta` не отправит случайно

Отправка идёт на серверы Apple под учётной записью владельца, попадает в
TestFlight и рассылается тестировщикам. Отозвать её нельзя — только выпустить
следующую, а сгоревший номер сборки занять повторно уже не выйдет. Поэтому
наличие ключей в окружении означает «право отправить», а не «намерение
отправить сейчас», и `beta` спрашивает отдельно:

- в терминале — вопросом «Отправлять?»;
- в CI, где спросить некого, — требует `VIBEE_TESTFLIGHT_CONFIRM=yes`.

Проверено запуском: `fastlane beta` без подтверждения в неинтерактивной
оболочке выполняет ровно два шага (`default_platform`, `xcodegen generate`) и
останавливается — ни сборки, ни обращения к Apple.

### Что ловит `preflight`

Всё это Apple проверяет тоже — но ПОСЛЕ сборки и загрузки, письмом через
несколько минут. Дешевле упасть за десять секунд:

- иконка на месте, ровно 1024×1024 и **без альфа-канала** (одного лишь
  «файл существует» мало: подложенный при проверке PNG 8×8 с прозрачностью
  проходил, а Apple отвергает и размер, и прозрачность — ITMS-90717);
- `actool` на этой машине вообще способен собрать каталог ресурсов;
- в связке ключей есть сертификат **Apple Distribution** (обычная локальная
  сборка подписывается сертификатом Apple Development, для выкладки он не
  годится);
- в настройках сборки есть `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION`.

`beta` вызывает `preflight` перед сборкой, так что мимо не пройдёт.

### Номер сборки не хранится в файлах

`fastlane bump` раньше звал `increment_build_number`. Проверено запуском:
тот откатывается на `agvtool new-version -all`, а `agvtool` правит
`Vibee/Info.plist` — файл ГЕНЕРИРУЕМЫЙ (его пишет xcodegen из `project.yml`)
и при этом отслеживаемый git. Выходило два поражения сразу: рабочее дерево
пачкалось при каждой выкладке, а следующий `xcodegen generate` затирал номер
обратно (вписанный `7` снова становился `1`).

Теперь версии живут настройками сборки в `project.yml`, а Info.plist на них
только ссылается:

```yaml
CFBundleShortVersionString: "$(MARKETING_VERSION)"
CFBundleVersion: "$(CURRENT_PROJECT_VERSION)"
```

`beta` спрашивает следующий свободный номер у Apple и передаёт его сборке
через `xcargs` — ни один файл на диске при этом не меняется.

### Что нужно один раз — и это НЕ моя часть

Всё ниже требует вашей учётной записи Apple. Я эти значения не ввожу и не
храню: ключ App Store Connect API даёт право выкладывать приложения от
вашего имени, и место ему — в менеджере секретов, а не в репозитории или в
переписке.

1. **Зарегистрировать приложение.** В App Store Connect создать запись с
   идентификатором `ai.t27.vibee` (или задать свой через `VIBEE_BUNDLE_ID`).

2. **Выпустить ключ App Store Connect API**: Users and Access → Integrations →
   App Store Connect API → плюс, роль **App Manager**.

   Файл `.p8` **скачивается ровно один раз**. Потеряли — выпускайте новый,
   восстановить нельзя.

3. **Выпустить сертификат Apple Distribution.** В связке ключей этой машины
   сейчас ровно один сертификат — `Apple Development`, а им подписывают
   сборку для своего устройства, не для App Store Connect. Выпуск требует
   роли Admin или Account Holder в Apple Developer.

4. **Дать иконку** — PNG 1024×1024, см. раздел «Иконка приложения».

5. **Задать четыре переменные** (в `~/.zshrc`, в Infisical или в секретах CI):

   | Переменная | Где взять |
   | --- | --- |
   | `ASC_KEY_ID` | рядом с ключом в списке |
   | `ASC_ISSUER_ID` | вверху страницы Integrations, один на команду |
   | `ASC_KEY_P8` | СОДЕРЖИМОЕ файла `.p8`, целиком, вместе со строками `BEGIN/END` |
   | `FASTLANE_TEAM_ID` | Membership → Team ID, десять символов |

   `ASC_KEY_P8` — многострочный. В `.zshrc` его удобно задать так:
   ```bash
   export ASC_KEY_P8="$(cat ~/.private/AuthKey_XXXXXXXX.p8)"
   ```
   Сам файл держите вне репозитория — `~/.private/` подойдёт.

Если переменных нет, `fastlane beta` останавливается СРАЗУ и называет
недостающие, а не падает через десять минут в конце сборки.

### Что fastlane делает сам

- **Генерирует `.xcodeproj`** из `project.yml` — ВСЕГДА, а не только когда
  файла нет. Проект в `.gitignore`, но остаётся на диске от прошлых запусков,
  и при `unless File.exist?` сборка молча шла по СТАРЫМ настройкам: правка
  версии или подписи просто не доезжала, а лог при этом был зелёный.
- **Берёт номер сборки у Apple**, а не из локального файла. Локальный
  счётчик разъезжается, как только собрали с другой машины, и выкладка
  падает на «build already exists» — уже после долгой сборки.
- **Не ждёт обработки** у Apple: она занимает от минут до часа, и держать
  процесс всё это время значит вешать CI на пустом месте.
- **Кладёт в заметки последний коммит** — человек в TestFlight должен
  понимать, что именно он тестирует.

### Подпись

`CODE_SIGNING_ALLOWED` отключён **только для симулятора**:

```yaml
"CODE_SIGNING_ALLOWED[sdk=iphonesimulator*]": NO
```

Безусловное отключение чинит локальную сборку и **молча ломает архив**:
подписать `.ipa` без подписи нельзя, и ошибка вылезет в конце.
