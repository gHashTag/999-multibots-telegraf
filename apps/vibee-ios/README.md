# Trinity S³AI — нативная оболочка для iOS

Нативный SwiftUI-контейнер поверх существующего мини-аппа. Задача была
«максимум нативного UI без большой переделки», поэтому переписаны экраны,
куда заходят КАЖДЫЙ раз, а те, куда заходят раз за сессию, остались вебом.

## Что нативное

| Экран | Чем сделан | Почему так |
| --- | --- | --- |
| Лента | SwiftUI + `AVPlayerLayer` | Вертикальный пейджинг, инерция и отскок от системы; `resizeAspectFill` даёт кадр во весь экран без полей |
| Агент | SwiftUI, потоковый NDJSON | Чат — самая частая точка входа |
| Профиль | SwiftUI | Простой список, переписывается за час |
| Редактор, ИИ | `WKWebView` | Холст, таймлайн и перетаскивание слоёв — месяцы работы на SwiftUI ради экрана, куда заходят раз за сессию |

## Сборка

На этой машине Xcode несёт SDK iOS 26.5, а из рантаймов установлен только
18.4. Из-за этого `xcodebuild` **не предлагает ни одного симуляторного
назначения** — в списке только устройства с «iOS 26.5 is not installed».
Поэтому собираем цель напрямую, минуя разрешение назначений:

```bash
xcodegen generate
xcodebuild -project Vibee.xcodeproj -target Vibee \
  -sdk iphonesimulator26.5 -configuration Debug -arch arm64 \
  SYMROOT=$PWD/build2 build

xcrun simctl install booted build2/Debug-iphonesimulator/Vibee.app
xcrun simctl launch booted ai.t27.vibee
```

## Одна полоса вкладок, а не две

Внутри `WKWebView` живёт собственная нижняя панель мини-аппа, и вместе с
нативной их видно ДВЕ. Прячем вебовую — на стороне контейнера, без
перевыпуска мини-аппа: тот же адрес открывается внутри Telegram, где эта
панель единственная и нужная.

Ищем панели **по геометрии**, а не по именам классов: приклеена к низу
(`fixed`/`sticky`), невысокая, во всю ширину. Перечисление селекторов уже
проиграло — на ленте поймало, в редакторе пропустило: там другие классы.

## Чего здесь нет

Полного нативного повторения редактора и генерации. Это не оболочка, а
переписывание продукта: холст со слоями, таймлайн с перетаскиванием,
предпросмотр рендера. Порядок, в котором это имеет смысл делать, — по
частоте входов, а не по списку экранов.

## Выкладка в TestFlight

```bash
cd apps/vibee-ios
fastlane preflight     # что мешает выкладке — за секунды, без учётной записи
fastlane build_only    # собрать .ipa для App Store, без отправки
fastlane beta          # собрать релиз и подготовить к отправке
```

**Отправка выключена.** В lane `beta` вызов `upload_to_testflight`
закомментирован. Это не забывчивость: отправка публикует сборку в App Store
Connect от имени владельца учётной записи, необратима (сборка получает
номер и уходит тестерам) и требует его ключа. Снять комментарий — осознанное
действие владельца, а не побочный эффект запуска команды. Флага для этого
намеренно нет: флаг можно выставить случайно, комментарий — нет.

### Начните с `fastlane preflight`

Он называет ВСЕ препятствия сразу, за секунды, и ничего не отправляет.
Состояние на 28 августа 2026 на машине разработки:

```
✓ схема Vibee общая (shared) — gym её найдёт
✓ иконка 1024×1024 без альфа-канала лежит в AppIcon.xcassets
✓ номер сборки будет 4822 (счёт коммитов)
✓ идентификатор приложения ai.t27.vibee
✗ AppIcon.xcassets НЕ подключён к цели
✗ платформа iOS для текущего SDK не установлена
✗ нет сертификата Apple Distribution
✗ не заданы переменные ключа ASC
```

Сначала печатается весь список, и только потом lane **падает** — код
возврата 1, если препятствие хоть одно. Раньше он возвращал 0: четыре
креста на экране и «успех» для любого скрипта, то есть `preflight &&
что-нибудь-дальше` ехало дальше. Гейт, который не может не пройти, — тот
самый худший вид гейта, о котором написано в `lefthook.yml` этого
репозитория.

Про иконку проверяется не имя файла, а сам файл: ширина, высота и
альфа-канал. Одного `File.exist?` мало — подставленный при проверке PNG
8×8 с прозрачностью проходил как годная иконка, хотя Apple отвергает его
дважды, за размер и за прозрачность (ITMS-90717). Сегодняшняя картинка в
порядке, но её заменят, а экспорт из большинства редакторов даёт альфу по
умолчанию.

### Что нужно один раз — и это НЕ моя часть

Всё ниже требует вашей учётной записи Apple либо доступа к этой машине. Я
эти значения не ввожу и не храню: ключ App Store Connect API даёт право
выкладывать приложения от вашего имени, и место ему — в менеджере секретов,
а не в репозитории или в переписке.

1. **Установить поддержку платформы iOS**:
   ```bash
   xcodebuild -downloadPlatform iOS
   ```
   Это НЕ формальность. Сейчас Xcode 26.6 несёт SDK iOS 26.5, а платформа
   не установлена, и из-за этого:
   - `xcodebuild archive` (то есть и `gym`) отвечает
     `Found no destinations for the scheme 'Vibee' and action archive` —
     архив невозможен вовсе, независимо от сертификатов;
   - `actool` отказывается собирать иконку:
     `No simulator runtime version from ["22E238"] available to use with
     iphonesimulator SDK version 23F81a`.

   Обычная сборка `-sdk iphoneos build` при этом проходит успешно. То есть
   зелёная сборка НЕ доказывает, что архив соберётся.

2. **Подключить иконку к цели.** В `project.yml` раскомментировать строку
   `- AppIcon.xcassets` в `sources`. Она выключена, пока не сделан пункт 1:
   с ней падает не только архив, но и ежедневный `./run.sh`. Рядом со
   строкой написано, что именно проверялось.

3. **Зарегистрировать приложение.** В App Store Connect создать запись с
   идентификатором `ai.t27.vibee` (или задать свой через `VIBEE_BUNDLE_ID`).

4. **Выпустить сертификат Apple Distribution** и профиль App Store для этого
   идентификатора — или войти Apple ID в Xcode → Settings → Accounts и дать
   автоподписи выпустить их. Сейчас в связке ключей есть только
   `Apple Development`, а им экспорт с `export_method: app-store` подписать
   нельзя.

5. **Выпустить ключ App Store Connect API**: Users and Access → Integrations →
   App Store Connect API → плюс, роль **App Manager**.

   Файл `.p8` **скачивается ровно один раз**. Потеряли — выпускайте новый,
   восстановить нельзя.

6. **Задать переменные** (в `~/.zshrc`, в Infisical или в секретах CI):

   | Переменная | Где взять | Обязательна |
   | --- | --- | --- |
   | `ASC_KEY_ID` | рядом с ключом в списке | да |
   | `ASC_ISSUER_ID` | вверху страницы Integrations, один на команду | да |
   | `ASC_KEY_P8` | СОДЕРЖИМОЕ файла `.p8`, целиком, со строками `BEGIN/END` | да |
   | `FASTLANE_TEAM_ID` | Membership → Team ID | нет, значение уже в Appfile |
   | `FASTLANE_ITC_TEAM_ID` | App Store Connect, если команд несколько | нет |
   | `VIBEE_BUILD` | ручной номер сборки вместо счёта коммитов | нет |

   `ASC_KEY_P8` — многострочный. В `.zshrc` его удобно задать так:
   ```bash
   export ASC_KEY_P8="$(cat ~/.private/AuthKey_XXXXXXXX.p8)"
   ```
   Сам файл держите вне репозитория — `~/.private/` подойдёт.

7. **Экспортное соответствие — уже отвечено в бандле.**
   `ITSAppUsesNonExemptEncryption: false` стоит в `project.yml` рядом с
   разбором каждого вызова криптографии: своей нет, Keychain и HTTPS —
   стандартные исключения Apple. Поэтому сборка больше не ждёт ручного
   ответа в App Store Connect и уходит тестерам сама.

   Заявление всё равно делается ОТ ВАШЕГО ИМЕНИ в момент загрузки: строка
   лишь избавляет от повторного вопроса, а не от ответственности.
   Появится своя криптография — значение пересматривать в том же коммите.

### Номер сборки — счёт коммитов, а не файл

`fastlane` НЕ вызывает `increment_build_number`. Тот зовёт `agvtool`, а он
правит `Vibee/Info.plist` — файл, который отслеживается git и который
**перегенерирует xcodegen** из `project.yml`. Проверено: agvtool пишет
`Updated CFBundleVersion … to 42`, следующий `xcodegen generate` возвращает
`1`, и выкладка уходит со старым номером. А `run.sh` зовёт `xcodegen`
безусловно.

Поэтому `Info.plist` ссылается на `$(CURRENT_PROJECT_VERSION)`, а номер
приезжает переменной сборки: `xcodebuild … CURRENT_PROJECT_VERSION=4813`.
Ни один файл при выкладке не меняется. Значение — `git rev-list --count HEAD`:
монотонно, одинаково на любой машине, не требует обращения к Apple.
Перекрывается переменной `VIBEE_BUILD`.

### Иконка

`AppIcon.xcassets/AppIcon.appiconset/AppIcon-1024.png` — 1024×1024, без
альфа-канала (App Store отклоняет иконки с прозрачностью). Это марка T27 из
`apps/vibee-editor/player/public/t27-mark.svg`, отрисованная на фоне
`#000000` — том самом `--bg-primary`, что в `Theme.swift`. Геометрия марки
не менялась.

**Это рабочая иконка, а не финальная.** В продукте живут три знака сразу:
марка T27 (она же в идентификаторе `ai.t27.vibee`), логотип VIBEE в
`player/public/logo.svg` и название `Trinity S³AI`. Какой из них должен
стоять на домашнем экране — решение владельца, а не сборки. Замена — один
PNG, ничего больше.

### Что fastlane делает сам

- **Генерирует `.xcodeproj`** из `project.yml` перед КАЖДЫМ lane, а не
  только когда файла нет. Проект в `.gitignore`, но остаётся на диске от
  прошлых запусков, и `unless File.exist?` означал бы сборку по старым
  настройкам. Проверено: в `project.yml` вписан `MARKETING_VERSION 9.9`, а
  `xcodebuild -showBuildSettings` на несвежем проекте по-прежнему отдаёт
  `1.0` — то есть `fastlane build_only` подписал бы старую версию, зелено
  и молча. Генерация занимает доли секунды.
- **Проверяет подпись и назначения ДО сборки.** Иначе отказ приходит на
  экспорте, через минуты компиляции.
- **Не пишет `.p8` на диск** — ключ живёт только в памяти процесса.
- **Читает `project.yml` с явной кодировкой UTF-8.** Без этого `File.read`
  берёт кодировку из локали, у fastlane она сплошь и рядом US-ASCII, и
  первая же строка с кириллицей роняет lane на
  `invalid byte sequence in US-ASCII`. Проверено запуском.

### Подпись

`CODE_SIGNING_ALLOWED` отключён **только для симулятора**:

```yaml
"CODE_SIGNING_ALLOWED[sdk=iphonesimulator*]": NO
```

Безусловное отключение чинит локальную сборку и **молча ломает архив**:
подписать `.ipa` без подписи нельзя, и ошибка вылезет в конце.

### Разрешения на камеру, микрофон и медиатеку

Их в бандле нет — и это проверено, а не забыто. Во всём `Vibee/` не
встречается ни `AVCaptureDevice`, ни `PhotosPicker`/`PHPhotoLibrary`, ни
`AVAudioRecorder`. Единственное обращение к медиа — `AVAudioSession
.setCategory(.playback)` в `FeedView.swift`, а воспроизведению разрешения не
нужны. Исходники для генерации приложение отправляет ссылками; файлы с
устройства не читаются.

Готовые тексты описаний лежат закомментированными в `project.yml` и
раскомментируются в том же коммите, где появится пикер или запись. Ключ
разрешения, которым приложение не пользуется, — не безобидная заготовка:
App Review спрашивает, где именно оно применяется.
