# Trinity S³AI — нативная оболочка для iOS

Нативный SwiftUI-контейнер поверх существующего мини-аппа. Задача была
«максимум нативного UI без большой переделки», поэтому переписаны экраны,
куда заходят КАЖДЫЙ раз, а те, куда заходят раз за сессию, остались вебом.

## Что нативное

| Экран        | Чем сделан                | Почему так                                                                                                |
| ------------ | ------------------------- | --------------------------------------------------------------------------------------------------------- |
| Лента        | SwiftUI + `AVPlayerLayer` | Вертикальный пейджинг, инерция и отскок от системы; `resizeAspectFill` даёт кадр во весь экран без полей  |
| Агент        | SwiftUI, потоковый NDJSON | Чат — самая частая точка входа                                                                            |
| Профиль      | SwiftUI                   | Простой список, переписывается за час                                                                     |
| Редактор, ИИ | `WKWebView`               | Холст, таймлайн и перетаскивание слоёв — месяцы работы на SwiftUI ради экрана, куда заходят раз за сессию |

## Сборка

На этой машине Xcode несёт SDK iOS 26.5, а из рантаймов установлен только
18.4. Из-за этого `xcodebuild` **не предлагает ни одного симуляторного
назначения** — в списке только устройства с «iOS 26.5 is not installed».
Поэтому собираем цель напрямую, минуя разрешение назначений:

```bash
xcodegen generate
xcodebuild -project Vibee.xcodeproj -target Vibee \
  -sdk iphonesimulator26.5 -configuration Debug -arch arm64 \
  SYMROOT=$PWD/build2 build

xcrun simctl install booted build2/Debug-iphonesimulator/Vibee.app
xcrun simctl launch booted ai.t27.vibee
```

## Одна полоса вкладок, а не две

Внутри `WKWebView` живёт собственная нижняя панель мини-аппа, и вместе с
нативной их видно ДВЕ. Прячем вебовую — на стороне контейнера, без
перевыпуска мини-аппа: тот же адрес открывается внутри Telegram, где эта
панель единственная и нужная.

Ищем панели **по геометрии**, а не по именам классов: приклеена к низу
(`fixed`/`sticky`), невысокая, во всю ширину. Перечисление селекторов уже
проиграло — на ленте поймало, в редакторе пропустило: там другие классы.

## Чего здесь нет

Полного нативного повторения редактора и генерации. Это не оболочка, а
переписывание продукта: холст со слоями, таймлайн с перетаскиванием,
предпросмотр рендера. Порядок, в котором это имеет смысл делать, — по
частоте входов, а не по списку экранов.

## Publishing to TestFlight and the App Store

The lanes are the ones the Leela app shipped with (`gHashTag/leela`,
`fastlane/Fastfile`), adapted to a project generated by xcodegen.

```bash
tri iphone store             # preflight + state: what stands between HEAD and TestFlight
tri iphone testflight --yes  # build and upload (the owner's call, never a loop's)

cd apps/vibee-ios
fastlane preflight   # every blocker at once, offline, in seconds; fails if any
fastlane state       # what App Store Connect holds (read-only)
fastlane certs       # fetch, or create, an Apple Distribution certificate
fastlane build_only  # signed App Store .ipa in build/ipa, nothing sent
fastlane beta        # state + build_only + upload_to_testflight (internal testers)
```

Nothing here submits for App Store review: `beta` stops at TestFlight, and
the review submission stays a click in App Store Connect.

### State on 2026-10-03

```
✓ scheme Vibee is shared - gym will find it
✓ 1024x1024 icon without alpha in AppIcon.xcassets
✓ AppIcon.xcassets is part of the target
✓ the scheme has archive destinations (iOS platform installed)
✓ Apple Distribution certificate in the keychain
✓ App Store Connect key R3JF4GL93F (file)
app id    ai.t27.vibee is NOT registered in Certificates, Identifiers & Profiles
[!] App Store Connect has no app with bundle id ai.t27.vibee.
```

The key works (it lists nine apps of the team, Leela among them). What is
missing is the account holder's, done once:

1. **The App ID** - developer.apple.com -> Identifiers -> +, explicit,
   `ai.t27.vibee`.
2. **The app record** - App Store Connect -> Apps -> + -> New App, same
   bundle id. Apple's API cannot create one, so no lane does.

After that `tri iphone store` should end in `next build N is above the
latest M`, and `tri iphone testflight --yes` uploads.

### The key

No secret is in this repository. The App Store Connect API key is read from
the same place `tri iphone` signs device builds with:

| What                        | Where                                                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| the `.p8`                   | `~/.appstoreconnect/private_keys/AuthKey_<KEY_ID>.p8`                                       |
| key id + issuer id          | `~/.appstoreconnect/fastlane-key.json` (`key_id`, `issuer_id`)                              |
| override on another machine | `ASC_KEY_ID`, `ASC_ISSUER_ID`; `ASC_KEY_P8` = the .p8 contents when there is no file (CI)   |
| optional                    | `VIBEE_BUILD` (build number), `VIBEE_BUNDLE_ID`, `FASTLANE_TEAM_ID`, `FASTLANE_ITC_TEAM_ID` |

A `.p8` downloads exactly once; lose it and a new key has to be issued.

Export compliance is already answered in the bundle:
`ITSAppUsesNonExemptEncryption: false` in `project.yml`, next to the review
of every crypto call. The declaration is still made in the owner's name at
upload; new cryptography means revisiting it in the same commit.

### What the lanes do, and the failure behind each

- **Generate the `.xcodeproj` before EVERY lane.** A stale project ignores
  `project.yml`: `MARKETING_VERSION 9.9` in the spec, `1.0` in
  `-showBuildSettings`, and `build_only` would have signed the old version.
- **Build number = `git rev-list --count HEAD`, passed as a build setting.**
  `increment_build_number` edits `Vibee/Info.plist`, which xcodegen
  regenerates back to 1. `state` refuses a number not above the latest
  TestFlight build - Apple rejects a reused number only after the upload.
- **The key authenticates provisioning on archive and export**
  (`-allowProvisioningUpdates -authenticationKey*`). Xcode here has no Apple
  ID; Leela's first export died on "No Accounts" without it.
- **macOS rsync during the build.** `-exportArchive` runs
  `/usr/bin/rsync -8aPhhE`; Homebrew's rsync rejects `-E` and the export
  fails as "exportArchive Copy failed" naming neither (Leela, found in
  Xcode's distribution logs). PATH is stripped for the build and restored.
- **No symbol upload from the export** (`uploadSymbols: false`): it looks for
  an Apple ID and dies with "Could not connect to the server";
  `upload_to_testflight` carries the dSYMs.
- **Raw xcodebuild output.** The stripped PATH hides xcpretty, and a missing
  formatter killed Leela's pipe with exit 127 after a successful archive.
- **Lanes run in `fastlane/`, so every path goes through `IOS_DIR`.** A
  relative `-project Vibee.xcodeproj` found nothing there, and `preflight`
  reported "iOS platform not installed" on a machine that had it.
- **`project.yml` is read as UTF-8.** fastlane's locale is often US-ASCII,
  and the first Cyrillic byte ends the lane; `tri` sets the locale too.

### The icon

`AppIcon.xcassets/AppIcon.appiconset/AppIcon-1024.png` is 1024x1024 without
alpha (the App Store rejects transparency). It is the T27 mark from
`apps/vibee-editor/player/public/t27-mark.svg` on `#000000`. It is a working
icon, not a final one: which of the three marks belongs on the home screen
is the owner's decision, and replacing it is one PNG.

It joined the target on 2026-10-03. Until then actool refused any app icon
because this machine had only the 18.4 simulator runtime for SDK 26.5; with
the 26.5 runtime installed it compiles for device and simulator, and the
simulator build carries `Assets.car` and `CFBundleIcons`.

### Подпись

`CODE_SIGNING_ALLOWED` отключён **только для симулятора**:

```yaml
'CODE_SIGNING_ALLOWED[sdk=iphonesimulator*]': NO
```

Безусловное отключение чинит локальную сборку и **молча ломает архив**:
подписать `.ipa` без подписи нельзя, и ошибка вылезет в конце.

### Разрешения на камеру, микрофон и медиатеку

Их в бандле нет — и это проверено, а не забыто. Во всём `Vibee/` не
встречается ни `AVCaptureDevice`, ни `PhotosPicker`/`PHPhotoLibrary`, ни
`AVAudioRecorder`. Единственное обращение к медиа — `AVAudioSession
.setCategory(.playback)` в `FeedView.swift`, а воспроизведению разрешения не
нужны. Исходники для генерации приложение отправляет ссылками; файлы с
устройства не читаются.

Готовые тексты описаний лежат закомментированными в `project.yml` и
раскомментируются в том же коммите, где появится пикер или запись. Ключ
разрешения, которым приложение не пользуется, — не безобидная заготовка:
App Review спрашивает, где именно оно применяется.
