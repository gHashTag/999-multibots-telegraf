# Остановить чужую параллельную сессию цикла

## When to Use This Skill

- Владелец говорит «останови <имя> сессию» / «отдай задачу мне».
- Две сессии правят одни файлы: PR ловит конфликт между push и merge, память
  цикла (`.claude/loop-state/*.md`) называет ветку, которую ведёт не ты, коммиты
  в `origin/main` идут каждые несколько минут от чужой ветки.
- Автономный цикл был перезапущен, и старая сессия всё ещё «крутится».

## Быстрый диагноз

```
# Найти сессию: свои сессии этого аккаунта, свежие сверху.
mcp__Claude_Code_Remote__list_sessions   (mine: true)
# В строке: id (session_...), title, session_status (RUNNING), ветка в
# session_context.outcomes[].git_info.branches, стоимость в usage.cost_usd.
mcp__Claude_Code_Remote__get_session      (session_id: <её id>)
```

Признак «крутится сама»: `session_status: RUNNING`, `task_summary` меняется,
`turn_handoff` есть. Если это цикл на `ScheduleWakeup` (сама себе назначает
следующий ход), **крон-триггера у неё НЕТ** — `list_triggers` вернёт пусто.
Значит, выключить расписание нечем: пробуждение живёт ВНУТРИ сессии.

## Почему SendMessage не работает

Облачная сессия в ДРУГОМ контейнере недостижима из `SendMessage`/`ListAgents`
(они видят только агентов ЭТОЙ машины или Remote Control). `list_sessions`
её показывает, но написать ей нельзя. Не трать на это ходы — сразу к контролю
через CCR.

## Как остановить (порядок)

```
# 1. Прервать текущий ход (мягко, на ближайшей точке).
mcp__Claude_Code_Remote__interrupt_session (session_id: <id>)
# 2. Проверить: если всё ещё RUNNING и это ScheduleWakeup-цикл — прерывание
#    остановит лишь текущий ход, а следующее самопробуждение вернёт её.
#    Погасить контейнер и снять самопланирование:
mcp__Claude_Code_Remote__archive_session   (session_id: <id>)
# get_session после: session_status == ARCHIVED, bucket COMPLETED.
```

`interrupt` = стоп текущего хода. `archive` = гасит контейнер, самопробуждение
не возобновится. Только `archive` реально завершает самопланирующийся цикл.

## Правила, которые нельзя нарушать

1. **Архивировать — по слову владельца** («останови …») или когда сессия явно
   лишняя/дублирующая. Архив может потерять её незакоммиченную работу в этом
   ходе. Если в `get_session` виден `staged_files` и активный коммит — это риск;
   владелец сказал «останови» = риск принят, иначе спроси.
2. **Свою работу веди на СВОЕЙ ветке.** Забрав задачу, не продолжай на её ветке
   — возьми свою (память цикла назовёт её), чтобы не наследовать её незалитое
   состояние.
3. **Проверь, не сделала ли она уже задачу.** Прежде чем делать «отданное»:
   `git fetch origin main && git log --oneline -8 origin/main`. Витки быстрые —
   она могла слить ровно эту задачу за минуты до остановки (замер 27.09: #8
   был слит #3134 за ~14 мин до остановки busy-pascal; переделывать было
   нечего).

## Замер 27.09.2026 (факты)

Сессия `busy-pascal` (`session_01W2ej…`, ветка `claude/busy-pascal-sn3mjg`,
цикл CRM каждые 15 мин, потрачено ~$174) остановлена по слову владельца.
`SendMessage` — «not reachable» (другой контейнер). `list_triggers` — пусто
(цикл на `ScheduleWakeup`, не крон). `interrupt_session` → всё ещё RUNNING →
`archive_session` → ARCHIVED. Её последняя задача (#8) уже была слита (#3134),
так что забирать было нечего — только не переделать.
