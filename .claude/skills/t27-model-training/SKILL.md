# Обучение моделей под t27

Замерено 08.09.2026. Каждое число здесь получено вызовом API или прогоном, а не
взято из головы. Где стоит «оценка» — это оценка.

## ⚡ РАЗВОРОТ 08.09.2026: учить писать .t27, а не Verilog

Владелец: «нам надо на спеках t27 писать! а они уже через t27c в любой другой».

Это снимает тупик, в который упёрлись четыре итерации. Я учил модель задаче
«спек → Verilog», а годных пар для неё **ноль** — генератор Verilog не имеет
транслятора выражений. Но настоящая задача другая: **писать сам спек**. Тогда
кодогенератор — отдельная забота компилятора, а корпусом становятся спеки,
написанные людьми.

| задача                              | годных примеров      |
| ----------------------------------- | -------------------- |
| спек → Verilog (прежняя цель)       | **0**                |
| **написание .t27** (настоящая цель) | **317** только в t27 |

Числа получены **их же прибором**, `t27c`, а не моими регулярками:

```
t27c classify      651 файл .t27, из них ИСХОДНИК 623 (95.7%)
t27c spec-status   IMPLEMENTED 317 | UNWRITTEN 190 | NOPARSE 69 | NOFN 69 | PARTIAL 6
```

**Обучать только на IMPLEMENTED.** 190 UNWRITTEN — это скелеты, тот же класс,
что пустые оболочки Verilog: они учат отвечать ничем. 69 NOPARSE не разбираются
вовсе.

### Честный пересчёт корпуса: моё «1257» было неверно дважды

| источник                 | файлов `.t27` | IMPLEMENTED                             |
| ------------------------ | ------------- | --------------------------------------- |
| t27 (замерено полностью) | 651           | **317**                                 |
| trinity `apps/website`   | 760           | **≈360** — оценка по выборке 40 (47.5%) |
| trios `apps/trios-macos` | 68            | не мерено                               |

Ошибка первая: **считал по расширению**. В выборке из trinity 25% дают
`NOPARSE` — они не на этом языке.

Ошибка вторая: **считал копии внутри веб-сайта как отдельный корпус**. 760 из
791 файла trinity лежат в `apps/website/public/t27/files/…`, то есть это
опубликованные копии спеков из других проектов, а не самостоятельное собрание.

### `classify` и `parse` отвечают на РАЗНЫЕ вопросы

Файл `apps/website/.../avs_reconf.t27` начинается с `module`, и `classify`
называет его **SOURCE 100%**. `t27c parse` его **не разбирает**.

Причина — второй диалект: `module avs-reconf;` с точкой с запятой, без
фигурных скобок, комментарии через `;`. В t27 пишут
`module automation::wrapup { … }`.

**Для корпуса брать `spec-status`, а не `classify`.** Первый отвечает «на этом
ли языке», второй — «похоже ли на код». Их собственная справка предупреждает об
одном направлении этой разницы; обратное направление такое же.

### ⚠️ `t27c parse` — НЕ ворота: он принимает пустоту

Замерено 08.09.2026. Каждый из этих ответов «разбирается успешно», код 0:

| вход                      | `parse` | `spec-status` |
| ------------------------- | ------- | ------------- |
| пустой файл               | **0**   | NOFN          |
| одни пробелы              | **0**   | NOFN          |
| один комментарий          | **0**   | NOFN          |
| `module m {}`             | **0**   | NOFN          |
| только `struct`, без `fn` | **0**   | NOFN          |

Это защитимо — пустой файл действительно синтаксически корректен, — и
бесполезно как ворота: **модель, научившаяся выдавать пустоту, получила бы
100%**.

Ворота = `parse` **И** `spec-status ∈ {IMPLEMENTED, PARTIAL}`. По отдельности
каждое — прибор, который не может упасть; за эту ночь таких нашлось три:
гейт тестов, проверявший ноль файлов; аудит, считавший пустые оболочки
годными; и этот.

`scripts/validate-t27.mjs --self-test <контрольный.t27>` прогоняет батарею из
семи вырожденных входов и требует отвергнуть каждый, плюс принять настоящий
спек. **Контроль обязателен и обязан быть IMPLEMENTED**: первый прогон
провалился на `specs/demos/simple_test.t27`, который сам NOFN, — и это поймал
контроль, а не удача.

### Прибор воспроизводим за пять минут

`bootstrap/` в t27 — это и есть `t27c`, крейт на Rust под MIT с лёгкими
зависимостями:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/gHashTag/t27.git
cd t27 && git sparse-checkout set bootstrap cli specs   # 26 МБ
cd bootstrap && cargo build --release                    # 5 минут
```

Его справка — сжатая запись тех же уроков, что добываются здесь заново.
`classify` существует потому, что «расширение .t27 — это имя файла, а не
объявление типа», и каждое отношение в проекте считалось по 618 там, где
честный знаменатель 584.

## Главное в одном абзаце

Обучать модель **с нуля под t27 не нужно**: язык Rust/Zig-подобный, и
предобученная кодовая модель его синтаксис уже знает. Нужна **LoRA-адаптация**.
Преграда — не железо и не архитектура, а **парный корпус**: официальный датасет
содержит 8 пар. При этом ещё **35 пар уже лежат в репозитории готовыми**, и
они дают 346K токенов — выше порога, который дорожная карта датасета сама
называет условием запуска обучения.

## Почему LoRA, а не с нуля

Спек t27 выглядит так (`specs/automation/wrapup-auto.t27`):

```
module automation::wrapup {
    use memory::notebooklm;
    const DEFAULT_NOTEBOOK : str = "t27-QUEEN-BRAIN";
    struct WrapUpInput { summary: str, files_modified: [str], issue_number: u32 }
    test "wrapup_run_uploads_source" ...
}
```

`module ns::name`, `use`, `const x : T = ...`, `struct` с типами `u32`/`str`/
`[str]`, встроенные `test "..."`. Ни одной конструкции, которой не было бы в
Rust или Zig. Модель, видевшая эти языки, тратит адаптацию на **словарь и
идиомы проекта**, а не на грамматику — это ровно тот случай, для которого LoRA и
существует.

Вывод, который экономит месяцы: **не начинайте с обучения токенизатора и с
нуля.** Троичные HSLM из `trinity-training` — отдельная исследовательская линия,
она не про генерацию кода.

## Railway: GPU не продают

На странице тарифов только память, CPU, трафик и диск. Раздел «VM pricing
(Beta)» — тоже CPU. **Дообучать LLM на Railway нельзя ни в каком размере**;
LoRA даже на 1.7B без видеокарты идёт сутками.

Что на Railway обучать УМЕСТНО — то, что под него и строилось: HSLM на 1.24М
троичных параметров (`trinity-training`, артефакт 248 КБ) и сетка IGLA RACE
(`trios-trainer-igla`). Обе CPU-first по замыслу.

### Цена, которую обычно забывают

Railway берёт по минутам **выделенных** ресурсов: память $10/ГБ/мес, CPU
$20/vCPU/мес. Значит платишь не за работу, а за то, что процесс держит память:

- 2 ГБ круглосуточно — **$20/мес**, 4 ГБ — **$40/мес**, независимо от нагрузки;
- сам ответ модели — доли цента.

Serverless усыпляет простаивающий сервис, но в документации прямо сказано:
первый запрос к спящему **может вернуть 502**, плюс холодный старт.

### Режим размышления на CPU — замер

`qwen3:1.7b`, только CPU, 8 ядер, вопрос на один абзац ответа:

|                 | токенов | время      |
| --------------- | ------- | ---------- |
| с размышлением  | 323     | **30.2 с** |
| без размышления | 22      | 0.8 с      |

**14.7× по токенам, 39.8× по времени.** Отключить размышление ради скорости
нельзя: без него модель 1.7B ответила негодно — просто переспросила. Планируя
думающую модель на CPU, считайте по этим множителям, а не по скорости обычной
генерации.

## Настоящая преграда IGLA CODER — корпус

`t27/dataset/igla-coder/v0.1/README.md` о себе честен, и это стоит уважать:

> **8 пар, ~31 КБ, ~7–10K токенов.** «IGLA CODER v0.1 CANNOT train a working

> Сгенерированного кода нет вовсе — только спеки и заглушки.

Их же дорожная карта: **v0.5 = ≥200K токенов, и только тогда запуск обучения
разрешён.**

### Но корпус уже есть — просто не собран

Замер по дереву `gHashTag/t27` (08.09.2026), каждая пара **подтверждена
собственной шапкой `t27c`** в сгенерированном файле:

|                  | значение                              |
| ---------------- | ------------------------------------- |
| пар подтверждено | **35** (против 8 в датасете)          |
| отброшено        | 7 (6 заглушек + 1 без шапки)          |
| спеки + код      | 1183 КБ                               |
| токенов          | **≈346K** (оценка при 3.5 байт/токен) |
| по языкам        | 31 Verilog, 4 Rust                    |

**Порог v0.5 (≥200K) перекрыт** — без единого запуска кодогенератора.
Сборщик: `scripts/harvest-igla-pairs.mjs` в этом скилле.

### Три ловушки сборки, каждая проверена на живом дереве

Цифра шла 46 → 42 → 1 → 35, и каждый шаг стоил бы порчи корпуса:

**1. Подстрока вместо сегмента пути.** `path.includes('gen')` совпадает с
«a-gen-t-runner»: `specs/server/api.t27` спарился с
`contrib/backend/agent-runner/src/api.rs` — написанным руками кодом. Сравнивать
надо сегменты, а не подстроки.

**2. Заглушки выглядят как результат генерации.** Шесть файлов в
`bootstrap/gen/rust/base/` несут баннер `AUTO-GENERATED STUB`, лежат в
генераторской папке и чисто парятся с настоящим спеком:

```rust
// AUTO-GENERATED STUB
pub fn ternary_add(a: i32, b: i32) -> i32 { a + b }  // Temporary stub
```

Обучить на этом — научить модель, что троичный сумматор это целочисленный `+`.
Уверенный, правдоподобный, неверный ответ — ровно то, против чего затевается
корпус из спеков.

**3. Имя модуля НЕ совпадает с именем файла, и это норма.** `gen-verilog`
пишет `Generated from t27 spec: SacredAttention` для `nn/attention.t27` —
генератор называет модуль, а не файл. Требование равенства отбраковало 41 пару
из 42. Имя надо записывать, но не требовать совпадения.

Диалектов шапки три: `Generated from t27 spec: Имя` (Verilog, без точки),
`Generated from .t27 spec` (Rust, без имени вовсе) и заглушечный баннер.

Сырого t27 (без пар) — 534 файла и 5.0 МБ только в `t27`, около 1.5М токенов;
по экосистеме больше. Этого хватает для дообучения **на язык**, но не на задачу
«спек → код»: для неё нужны именно пары.

## Слабые места корпуса — замерены, не предположены

**1. Это 35 ДЛИННЫХ примеров, а не 346K коротких.** В среднем 9.9K токенов на
пару. LoRA учится от числа ПРИМЕРОВ, а не от объёма токенов, и 35 — очень мало.
Связывающее ограничение здесь именно это.

**2. Перекос 31 Verilog / 4 Rust (89/11).** Случайное разбиение может оставить
ноль Rust в оценке — и тогда утрата умения писать Rust не будет замечена вовсе.
Поэтому разбиение стратифицированное и детерминированное.

**3. Длина.** При контексте 8K не влезают **13 пар из 35**; при 32K — только 2.

| контекст | выброшено | обучение | оценка |
| -------- | --------- | -------- | ------ |
| 8K       | 13        | 17       | 5      |
| **32K**  | **2**     | **26**   | **7**  |

Отсюда требование к базе: **≥32K контекста**. Все четыре кандидата подходят.
Обрезать длинные пары нельзя: модель увидит полный спек, чей ответ обрывается,
и самым частым уроком в данных станет «генерируй примерно досюда и замолкай».

### Отрицательный результат: резать по модулям НЕ выходит

Напрашивалось разрезать длинные пары на мелкие и разом починить и «мало
примеров», и «не влезает». Проверено на живых файлах — **крупные
сгенерированные Verilog-файлы содержат ровно один модуль**: 60 КБ это один
модуль, 46 КБ — один. Делится только Rust (12 функций в одном файле).

Поэтому единственный настоящий рычаг — **больше пар**: спеков 493, вывод
закоммичен у 35. Прогон кодогенератора по остальным 458 даёт кратный рост
числа примеров, и это надо делать ДО споров о ранге и эпохах.

## Конкуренты: задача решена до нас, и это хорошая новость

Замер по HF 08.09.2026. Генерация Verilog из спецификации — не наша выдумка, по
ней есть модели, датасеты и эталон. Наш корпус на 89% Verilog, значит всё это
применимо напрямую.

|                                            | примеров                   | лицензия                             |
| ------------------------------------------ | -------------------------- | ------------------------------------ |
| `davide221/verilog-instruct-60k`           | **60 199**                 | не указана — **риск**                |
| `GaTech-EIC/MG-Verilog`                    | многоуровневый             | MIT                                  |
| `shailja/Verilog_GitHub` (VeriGen)         | корпус с GitHub            | MIT                                  |
| `dakies/nvlabs-verilogeval-v2-spec-to-rtl` | **156 задач**              | MIT                                  |
| `bnadimi/PyraNet-Verilog`                  | —                          | **CC-BY-NC-SA — коммерчески НЕЛЬЗЯ** |
| **наш корпус**                             | **26 обучение / 7 оценка** | Apache-2.0                           |

Готовые модели: `Nellyw888/VeriReason-Qwen2.5-{1.5b,3b}-RTLCoder-Verilog-GRPO`
— уже дообучены на Verilog поверх Qwen2.5, есть размер 1.5B.

### Что из этого следует — и в чём я был неправ

**Начинать надо не с общей кодовой модели.** Я рекомендовал `Qwen3-1.7B`
как базу. Для корпуса, где 89% Verilog, это второй по качеству выбор: разумнее
взять базу, УЖЕ обученную на Verilog (линия RTLCoder/VeriReason), и адаптировать
поверх неё только **диалект t27**. Тогда наши 26 примеров тратятся на то, чем мы
отличаемся, а не на язык, который кто-то уже оплатил.

**Оценивать на 7 примерах бессмысленно.** VerilogEval v2 spec-to-RTL — 156
задач под MIT и ровно наша постановка «спецификация → RTL». Наши 7 пар не
различают ничего; брать надо эталон, а свои 7 держать как проверку диалекта.

**PyraNet не трогать.** CC-BY-NC-SA запрещает коммерческое использование, а
платформа коммерческая. Лицензия `verilog-instruct-60k` не указана вовсе — до
выяснения считать непригодной.

Разрыв в данных — 26 против 60 199, то есть в 2300 раз. Это не приговор для
LoRA поверх готовой Verilog-базы, но приговор для попытки научить Verilog с нуля
на нашем корпусе.

## ⛔ Годных Verilog-пар — НОЛЬ из 31

Замерено 08.09.2026 через `iverilog`. Это перевешивает всё остальное в скилле.

|                                      |       |
| ------------------------------------ | ----- |
| Verilog-пар                          | 31    |
| **компилируется**                    | **2** |
| не компилируется                     | 29    |
| с протечкой Zig (`@as`, `[32]u16{}`) | 6     |
| с `namespace::` и математикой спека  | 11    |

Генератор выдаёт **транслитерацию спека, а не синтезируемый RTL**:

```verilog
reg [31:0] freq = pow(constants::PHI, freq_exponent);
```

`constants::PHI` — пространство имён t27, не Verilog. `pow`/`cos`/`sin` не имеют
аппаратного смысла. Объявления `reg` внутри `while`, где Verilog их не
допускает.

**Это ловушка с заглушкой в масштабе.** Шесть заглушек мы отбросили, потому что
они учили «троичный сумматор это целочисленный плюс». Эти 29 учат тише и хуже:
что правдоподобный несобирающийся Verilog — приемлемый ответ.

**И это переворачивает план.** «Прогнать генератор по остальным 458 спекам» был
главным рычагом объёма. Сегодня он размножит несобирающиеся данные. Сначала
генератор должен выдавать компилируемое, и только потом объём имеет цену.

Два «компилирующихся» файла компилируются **потому что пусты**:

```verilog
function [31:0] get_golden_ratio; // -> f64
    // TODO: implement
endfunction
```

`constants.v` имеет 13 констант в спеке и **ноль `parameter`** на выходе.
Пустая оболочка для обучения хуже сломанного файла: сломанный отбрасывают, а
пустой выглядит чистым примером и учит отвечать ничем.

Проверка: `tri igla audit` — число пересчитывается по мере починки генератора.

## ✅ Датасет для написания спеков собран

`scripts/build-spec-dataset.mjs`, прогон 08.09.2026 по репозиторию t27:

|                                |              |
| ------------------------------ | ------------ |
| просмотрено файлов             | 651          |
| отброшено: не IMPLEMENTED      | 334          |
| отброшено: без описания        | 70           |
| **примеров**                   | **241**      |
| обучение / оценка              | **207 / 34** |
| областей (стратификация)       | 32           |
| запрос содержит ответ          | **0**        |
| подозрительно коротких ответов | **0**        |

**Задача:** запрос — путь модуля и его описание; ответ — спек **начиная с
`module`**. Описание вырезано из ответа намеренно: оставь его — и первое, чему
модель научится, это возвращать текст, который ей только что дали. Тот же класс
ошибки, что баннер `t27c` в прежнем датасете.

**Только IMPLEMENTED.** UNWRITTEN и NOFN разбираются, выглядят чистыми
примерами и учат отвечать ничем.

### Проверка, которая сошлась — и почему ей всё равно нельзя верить на слово

**241 из 241** целей проходят те же ворота, которыми будет судиться модель.
Первая за ночь самопроверка, сошедшаяся с первого раза, — поэтому она
дополнительно проверена мутацией на тех же данных:

| вход                  | ворота     |
| --------------------- | ---------- |
| целый спек            | пропустили |
| обрезан пополам       | отвергли   |
| одна первая строка    | отвергли   |
| тела функций вырезаны | отвергли   |

Без этого «241 из 241» было бы неотличимо от ворот, которые пропускают всё.

## ⛔ Валидность — не правильность: ворота давали жульнику 100%

Проверка 08.09.2026. «Жульник» отвечает на КАЖДЫЙ из 34 вопросов одним и тем же
чужим, но валидным спеком из обучающей выборки:

| отвечающий    | VALID    | RELEVANT | SUBSTANCE |
| ------------- | -------- | -------- | --------- |
| эталон        | 100%     | 100%     | 100%      |
| **жульник**   | **100%** | **0%**   | **0%**    |
| пустые ответы | 0%       | 0%       | 0%        |

Столбец VALID — это прежние ворота (`parse` + `spec-status`). Они дают жульнику
**сто процентов**. Любой результат обучения, прочитанный по ним, был бы
бессмыслицей и выглядел бы успехом.

Измеряется теперь три вещи, раздельно, потому что ломаются они по-разному:

- **VALID** — разбирается и содержит функции;
- **RELEVANT** — объявлен ли ТОТ модуль, который спросили (это и убивает жульника:
  нельзя быть `github::issues` и `nn::attention` одновременно);
- **SUBSTANCE** — доля имён эталона, встретившихся в ответе. Намеренно дробь, а
  не «прошёл/не прошёл»: два верных спека могут называть вещи по-разному.

Прибор: `scripts/score-spec-answers.mjs --self-test`.

### Батарея, которая сама требует большой вход

`validate-t27.mjs --self-test <контроль>` теперь **отказывается считать себя
полной**, если AST контроля не превышает 1 МБ:

```
маленький контроль (issues.t27, AST 16 КБ):
  ⚠️ БАТАРЕЯ НЕПОЛНАЯ: нужен AST больше 1024 КБ
большой контроль (base/ops.t27, AST 2.4 МБ):
  ✅ размерный класс покрыт
```

Соотношение измерено: **≈53 байта AST на байт спека**, то есть любой спек
крупнее ~20 КБ переполнял бы старый буфер.

Доказано мутацией: с возвращённым багом `maxBuffer` батарея краснеет
(«контроль ОТВЕРГНУТ»), без него зелёная.

### ⚠️ Мутация, которая не применилась, выглядит как пойманная ошибка

Первая попытка этой мутации **не применилась**: в файле отступ 4 пробела, в моей
замене было 6. Батарея осталась зелёной, и вывод напрашивался ложный — «она не
ловит баг». На самом деле баг не был внесён.

Для этого в проекте есть `tri blind`, который ОТКАЗЫВАЕТСЯ работать, если
образец не найден. Правило: любая ручная мутация обязана утверждать, что
подстановка состоялась, — иначе молчаливый промах неотличим от защиты.

### Самопроверка из маленьких входов не найдёт ошибку, зависящую от размера

`t27c parse` печатает AST в stdout. У больших спеков он **превышает буфер
`execFile` в 1 МБ**, Node бросает `stdout maxBuffer length exceeded`, а
`catch { return false }` считает это провалом разбора.

То есть VALID мерил «помещается ли AST в буфер». Эталон давал 79% вместо 100%,
а заведомо валидный спек — 0%.

Та же ошибка лежала в `validate-t27.mjs`, **который был «поверен» итерацией
раньше**: его батарея состояла из пустого файла, пробелов, комментария и
`module m {}` — всё крошечное. Батарея из маленьких входов не может поймать
ошибку, зависящую от размера. Лечение — `maxBuffer` и хотя бы один большой
настоящий вход в каждой батарее.

## Напечатанное и не утверждённое — украшение

Перепись приборов 08.09.2026: **у четырёх из семи самоповерки нет вовсе**, и это
ровно те, чьи числа пришлось отзывать (46→35 пар, 2→0 годных, баннер в целях).

Но хуже другое. Поверка измерителя ответов **видела** вчерашний баг `maxBuffer`:
эталон показывал `VALID 79%` вместо 100% — это в точности те 7 из 34 эталонов,
чей AST больше мегабайта. Число стояло на экране, а вердикт смотрел на другой
столбец и печатал «прибор поверен».

Теперь **на каждый печатаемый столбец есть утверждение**, и нарушенное
утверждение — ненулевой код возврата. Доказано мутацией: с возвращённым багом
поверка падает («эталон валиден лишь на 79%»), без него проходит.

То же в сборщике датасета: он три итерации печатал число утечек и вышел бы с
кодом 0 при любом из них, отдав испорченные данные как успешные.

### Страж, нацеленный не в ту сторону, не ловит ничего

Детектор утечки спрашивал: «содержит ли ЗАПРОС начало ОТВЕТА». Мутация,
возвращающая описание в цель — тот самый дефект, ради которого датасет и
строился, — прошла его чисто: цель начиналась с SPDX-строки, которой в запросе
не было.

Утечка, которая важна, обратная: **ОТВЕТ повторяет то, что модели только что
дали**. Именно это делает копирование самым дешёвым способом снизить потерю.
После разворота проверки мутация ловится: код 1, «58 запросов содержат ответ».

### Код возврата после конвейера — не код скрипта

`node x.mjs | tail -5; echo $?` печатает статус `tail`. Проверка «сломанный
прибор возвращает 1» дважды показала 0 именно поэтому. Справка `t27c gates`
предупреждает об этом же: так тринадцать гейтов рапортовали зелёным при двух
падающих.

## Диалекты: вопрос закрыт замером, а не решением

Третью итерацию я откладывал это «к владельцу». Померил — и решать нечего.

**Оба диалекта разбираются `t27c`.** Ни один не является ошибочным:

| диалект          | IMPLEMENTED | UNWRITTEN | доля написанных |
| ---------------- | ----------- | --------- | --------------- |
| `module x { … }` | 184         | 7         | **79%**         |
| `module x;`      | 127         | 183       | **32%**         |

Скобочная форма — там, где работа сделана; форма с точкой с запятой — там, где
в основном скелеты. Это не два языка, а два состояния.

**Задача поставлена корректно: 24 области из 32 однородны по диалекту**, то есть
он предсказуем по пути модуля. Смешанных восемь, и почти все с явным перевесом
(`fpga` 65/3, `numeric` 41/4, `igla` 8/30). Действительно неоднозначных —
единицы (`memory` 2/2).

В собранном датасете 73% скобочных и 27% с точкой с запятой — примерно как в
корпусе.

## Конфигурация указывала на заброшенные данные

Найдено 08.09.2026 чтением, а не прогоном. `lora-config.yaml` три итерации
указывал на `lora-dataset/` — **набор спек→Verilog, от которого отказались**, —
пока живым был `spec-dataset/`. Арендуй кто-нибудь GPU и запусти: обучение
пошло бы на 26 примерах несобирающегося Verilog вместо 207 спеков, и ошибка
обнаружилась бы по счёту за аренду.

Хуже указателя было то, что **все числа в ней выведены для тех данных**.
Перемерено под нынешние:

|                    | обучение (207) | оценка (34) |
| ------------------ | -------------- | ----------- |
| медиана            | 2690 токенов   | 2250        |
| p95                | 20 365         | 36 650      |
| максимум           | 33 009         | **55 172**  |
| не влезает в 32768 | 1 (0.5%)       | **3 (9%)**  |

**⚠️ Потолок оценки 91%, а не 100%.** У базы `Qwen2.5-Coder-1.5B` окно ровно
32768, а три оценочных вопроса длиннее. Модель физически не может на них
ответить; считать это её ошибкой нельзя. Кто увидит 91% и не будет знать —
решит, что модель плоха.

Проверка: `tri igla config` — сверяет, на какие данные смотрит конфигурация и
что лежит на диске.

### Чего оценка НЕ измеряет

Прибор меряет валидность, релевантность и долю совпавших имён. Спек может быть
валидным, релевантным и **делать не то**. Это не ловится ничем, кроме человека
или прогона тестов из самого спека, и об этом честно написано в конфигурации.

## Ловушка, из-за которой обучение не оставит файла

`trios-trainer-igla` — README сам предупреждает:

> Цифры BPB **отозваны**. `checkpoint::save` (`src/checkpoint.rs:116`) — заглушка,
> возвращающая `Ok(())` и не пишущая ничего. **Модельных артефактов на диске нет
> ни для одной цифры.**

Настоящее атомарное сохранение — в ветке `fix/509-qat-v2`, **не влито**.

**Поэтому: сначала влить сохранение чекпоинта, потом запускать что угодно.**
Иначе прогон отработает, отрапортует метрику и не оставит файла — это уже
происходило.

Состояние гонки на 08.09.2026: чемпион `gf256 × adamw` = BPB **2.5719**,
заморожен с 14 мая, цель <1.50, разрыв −1.07. Открыто: #217 (ядро nf4 не
обучается, delta_bpb=0.0), #230 (doctor-loop лежит, PAT истёк), #175 (застой
чемпиона).

## Порядок, если решено делать кодер

1. Влить `fix/509-qat-v2` — иначе артефакта не будет.
2. Собрать пары: `node scripts/harvest-igla-pairs.mjs` → 35 пар / ~346K токенов.
3. Прогнать кодогенератор по остальным спекам, чтобы довести до сотен пар.
4. LoRA поверх `Qwen3-1.7B` — **на арендованной GPU на часы**, не на Railway.
5. Railway оставить под HSLM и IGLA RACE, где CPU по делу.

## Чего не делать

- Не обещать дообучение LLM на Railway — там нет GPU.
- Не считать сырые `.t27` парным корпусом: 1.5М токенов языка ≠ данные «спек → код».
- Не запускать обучение до влития сохранения чекпоинта.
- Не оценивать думающую модель на CPU по скорости обычной генерации: множитель
  измерен и он почти сорокакратный по времени.
