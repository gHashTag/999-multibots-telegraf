# Обучение моделей под t27

Замерено 08.09.2026. Каждое число здесь получено вызовом API или прогоном, а не
взято из головы. Где стоит «оценка» — это оценка.

## Главное в одном абзаце

Обучать модель **с нуля под t27 не нужно**: язык Rust/Zig-подобный, и
предобученная кодовая модель его синтаксис уже знает. Нужна **LoRA-адаптация**.
Преграда — не железо и не архитектура, а **парный корпус**: официальный датасет
содержит 8 пар. При этом ещё **35 пар уже лежат в репозитории готовыми**, и
они дают 346K токенов — выше порога, который дорожная карта датасета сама
называет условием запуска обучения.

## Почему LoRA, а не с нуля

Спек t27 выглядит так (`specs/automation/wrapup-auto.t27`):

```
module automation::wrapup {
    use memory::notebooklm;
    const DEFAULT_NOTEBOOK : str = "t27-QUEEN-BRAIN";
    struct WrapUpInput { summary: str, files_modified: [str], issue_number: u32 }
    test "wrapup_run_uploads_source" ...
}
```

`module ns::name`, `use`, `const x : T = ...`, `struct` с типами `u32`/`str`/
`[str]`, встроенные `test "..."`. Ни одной конструкции, которой не было бы в
Rust или Zig. Модель, видевшая эти языки, тратит адаптацию на **словарь и
идиомы проекта**, а не на грамматику — это ровно тот случай, для которого LoRA и
существует.

Вывод, который экономит месяцы: **не начинайте с обучения токенизатора и с
нуля.** Троичные HSLM из `trinity-training` — отдельная исследовательская линия,
она не про генерацию кода.

## Railway: GPU не продают

На странице тарифов только память, CPU, трафик и диск. Раздел «VM pricing
(Beta)» — тоже CPU. **Дообучать LLM на Railway нельзя ни в каком размере**;
LoRA даже на 1.7B без видеокарты идёт сутками.

Что на Railway обучать УМЕСТНО — то, что под него и строилось: HSLM на 1.24М
троичных параметров (`trinity-training`, артефакт 248 КБ) и сетка IGLA RACE
(`trios-trainer-igla`). Обе CPU-first по замыслу.

### Цена, которую обычно забывают

Railway берёт по минутам **выделенных** ресурсов: память $10/ГБ/мес, CPU
$20/vCPU/мес. Значит платишь не за работу, а за то, что процесс держит память:

- 2 ГБ круглосуточно — **$20/мес**, 4 ГБ — **$40/мес**, независимо от нагрузки;
- сам ответ модели — доли цента.

Serverless усыпляет простаивающий сервис, но в документации прямо сказано:
первый запрос к спящему **может вернуть 502**, плюс холодный старт.

### Режим размышления на CPU — замер

`qwen3:1.7b`, только CPU, 8 ядер, вопрос на один абзац ответа:

|                 | токенов | время      |
| --------------- | ------- | ---------- |
| с размышлением  | 323     | **30.2 с** |
| без размышления | 22      | 0.8 с      |

**14.7× по токенам, 39.8× по времени.** Отключить размышление ради скорости
нельзя: без него модель 1.7B ответила негодно — просто переспросила. Планируя
думающую модель на CPU, считайте по этим множителям, а не по скорости обычной
генерации.

## Настоящая преграда IGLA CODER — корпус

`t27/dataset/igla-coder/v0.1/README.md` о себе честен, и это стоит уважать:

> **8 пар, ~31 КБ, ~7–10K токенов.** «IGLA CODER v0.1 CANNOT train a working
> model. This is a seed, not a corpus.» На три порядка ниже порога phi-1-small.
> Сгенерированного кода нет вовсе — только спеки и заглушки.

Их же дорожная карта: **v0.5 = ≥200K токенов, и только тогда запуск обучения
разрешён.**

### Но корпус уже есть — просто не собран

Замер по дереву `gHashTag/t27` (08.09.2026), каждая пара **подтверждена
собственной шапкой `t27c`** в сгенерированном файле:

|                  | значение                              |
| ---------------- | ------------------------------------- |
| пар подтверждено | **35** (против 8 в датасете)          |
| отброшено        | 7 (6 заглушек + 1 без шапки)          |
| спеки + код      | 1183 КБ                               |
| токенов          | **≈346K** (оценка при 3.5 байт/токен) |
| по языкам        | 31 Verilog, 4 Rust                    |

**Порог v0.5 (≥200K) перекрыт** — без единого запуска кодогенератора.
Сборщик: `scripts/harvest-igla-pairs.mjs` в этом скилле.

### Три ловушки сборки, каждая проверена на живом дереве

Цифра шла 46 → 42 → 1 → 35, и каждый шаг стоил бы порчи корпуса:

**1. Подстрока вместо сегмента пути.** `path.includes('gen')` совпадает с
«a-gen-t-runner»: `specs/server/api.t27` спарился с
`contrib/backend/agent-runner/src/api.rs` — написанным руками кодом. Сравнивать
надо сегменты, а не подстроки.

**2. Заглушки выглядят как результат генерации.** Шесть файлов в
`bootstrap/gen/rust/base/` несут баннер `AUTO-GENERATED STUB`, лежат в
генераторской папке и чисто парятся с настоящим спеком:

```rust
// AUTO-GENERATED STUB
pub fn ternary_add(a: i32, b: i32) -> i32 { a + b }  // Temporary stub
```

Обучить на этом — научить модель, что троичный сумматор это целочисленный `+`.
Уверенный, правдоподобный, неверный ответ — ровно то, против чего затевается
корпус из спеков.

**3. Имя модуля НЕ совпадает с именем файла, и это норма.** `gen-verilog`
пишет `Generated from t27 spec: SacredAttention` для `nn/attention.t27` —
генератор называет модуль, а не файл. Требование равенства отбраковало 41 пару
из 42. Имя надо записывать, но не требовать совпадения.

Диалектов шапки три: `Generated from t27 spec: Имя` (Verilog, без точки),
`Generated from .t27 spec` (Rust, без имени вовсе) и заглушечный баннер.

Сырого t27 (без пар) — 534 файла и 5.0 МБ только в `t27`, около 1.5М токенов;
по экосистеме больше. Этого хватает для дообучения **на язык**, но не на задачу
«спек → код»: для неё нужны именно пары.

## Слабые места корпуса — замерены, не предположены

**1. Это 35 ДЛИННЫХ примеров, а не 346K коротких.** В среднем 9.9K токенов на
пару. LoRA учится от числа ПРИМЕРОВ, а не от объёма токенов, и 35 — очень мало.
Связывающее ограничение здесь именно это.

**2. Перекос 31 Verilog / 4 Rust (89/11).** Случайное разбиение может оставить
ноль Rust в оценке — и тогда утрата умения писать Rust не будет замечена вовсе.
Поэтому разбиение стратифицированное и детерминированное.

**3. Длина.** При контексте 8K не влезают **13 пар из 35**; при 32K — только 2.

| контекст | выброшено | обучение | оценка |
| -------- | --------- | -------- | ------ |
| 8K       | 13        | 17       | 5      |
| **32K**  | **2**     | **26**   | **7**  |

Отсюда требование к базе: **≥32K контекста**. Все четыре кандидата подходят.
Обрезать длинные пары нельзя: модель увидит полный спек, чей ответ обрывается,
и самым частым уроком в данных станет «генерируй примерно досюда и замолкай».

### Отрицательный результат: резать по модулям НЕ выходит

Напрашивалось разрезать длинные пары на мелкие и разом починить и «мало
примеров», и «не влезает». Проверено на живых файлах — **крупные
сгенерированные Verilog-файлы содержат ровно один модуль**: 60 КБ это один
модуль, 46 КБ — один. Делится только Rust (12 функций в одном файле).

Поэтому единственный настоящий рычаг — **больше пар**: спеков 493, вывод
закоммичен у 35. Прогон кодогенератора по остальным 458 даёт кратный рост
числа примеров, и это надо делать ДО споров о ранге и эпохах.

## Конкуренты: задача решена до нас, и это хорошая новость

Замер по HF 08.09.2026. Генерация Verilog из спецификации — не наша выдумка, по
ней есть модели, датасеты и эталон. Наш корпус на 89% Verilog, значит всё это
применимо напрямую.

|                                            | примеров                   | лицензия                             |
| ------------------------------------------ | -------------------------- | ------------------------------------ |
| `davide221/verilog-instruct-60k`           | **60 199**                 | не указана — **риск**                |
| `GaTech-EIC/MG-Verilog`                    | многоуровневый             | MIT                                  |
| `shailja/Verilog_GitHub` (VeriGen)         | корпус с GitHub            | MIT                                  |
| `dakies/nvlabs-verilogeval-v2-spec-to-rtl` | **156 задач**              | MIT                                  |
| `bnadimi/PyraNet-Verilog`                  | —                          | **CC-BY-NC-SA — коммерчески НЕЛЬЗЯ** |
| **наш корпус**                             | **26 обучение / 7 оценка** | Apache-2.0                           |

Готовые модели: `Nellyw888/VeriReason-Qwen2.5-{1.5b,3b}-RTLCoder-Verilog-GRPO`
— уже дообучены на Verilog поверх Qwen2.5, есть размер 1.5B.

### Что из этого следует — и в чём я был неправ

**Начинать надо не с общей кодовой модели.** Я рекомендовал `Qwen3-1.7B`
как базу. Для корпуса, где 89% Verilog, это второй по качеству выбор: разумнее
взять базу, УЖЕ обученную на Verilog (линия RTLCoder/VeriReason), и адаптировать
поверх неё только **диалект t27**. Тогда наши 26 примеров тратятся на то, чем мы
отличаемся, а не на язык, который кто-то уже оплатил.

**Оценивать на 7 примерах бессмысленно.** VerilogEval v2 spec-to-RTL — 156
задач под MIT и ровно наша постановка «спецификация → RTL». Наши 7 пар не
различают ничего; брать надо эталон, а свои 7 держать как проверку диалекта.

**PyraNet не трогать.** CC-BY-NC-SA запрещает коммерческое использование, а
платформа коммерческая. Лицензия `verilog-instruct-60k` не указана вовсе — до
выяснения считать непригодной.

Разрыв в данных — 26 против 60 199, то есть в 2300 раз. Это не приговор для
LoRA поверх готовой Verilog-базы, но приговор для попытки научить Verilog с нуля
на нашем корпусе.

## ⛔ Годных Verilog-пар — НОЛЬ из 31

Замерено 08.09.2026 через `iverilog`. Это перевешивает всё остальное в скилле.

|                                      |       |
| ------------------------------------ | ----- |
| Verilog-пар                          | 31    |
| **компилируется**                    | **2** |
| не компилируется                     | 29    |
| с протечкой Zig (`@as`, `[32]u16{}`) | 6     |
| с `namespace::` и математикой спека  | 11    |

Генератор выдаёт **транслитерацию спека, а не синтезируемый RTL**:

```verilog
reg [31:0] freq = pow(constants::PHI, freq_exponent);
```

`constants::PHI` — пространство имён t27, не Verilog. `pow`/`cos`/`sin` не имеют
аппаратного смысла. Объявления `reg` внутри `while`, где Verilog их не
допускает.

**Это ловушка с заглушкой в масштабе.** Шесть заглушек мы отбросили, потому что
они учили «троичный сумматор это целочисленный плюс». Эти 29 учат тише и хуже:
что правдоподобный несобирающийся Verilog — приемлемый ответ.

**И это переворачивает план.** «Прогнать генератор по остальным 458 спекам» был
главным рычагом объёма. Сегодня он размножит несобирающиеся данные. Сначала
генератор должен выдавать компилируемое, и только потом объём имеет цену.

Два «компилирующихся» файла компилируются **потому что пусты**:

```verilog
function [31:0] get_golden_ratio; // -> f64
    // TODO: implement
endfunction
```

`constants.v` имеет 13 констант в спеке и **ноль `parameter`** на выходе.
Пустая оболочка для обучения хуже сломанного файла: сломанный отбрасывают, а
пустой выглядит чистым примером и учит отвечать ничем.

Проверка: `tri igla audit` — число пересчитывается по мере починки генератора.

## Ловушка, из-за которой обучение не оставит файла

`trios-trainer-igla` — README сам предупреждает:

> Цифры BPB **отозваны**. `checkpoint::save` (`src/checkpoint.rs:116`) — заглушка,
> возвращающая `Ok(())` и не пишущая ничего. **Модельных артефактов на диске нет
> ни для одной цифры.**

Настоящее атомарное сохранение — в ветке `fix/509-qat-v2`, **не влито**.

**Поэтому: сначала влить сохранение чекпоинта, потом запускать что угодно.**
Иначе прогон отработает, отрапортует метрику и не оставит файла — это уже
происходило.

Состояние гонки на 08.09.2026: чемпион `gf256 × adamw` = BPB **2.5719**,
заморожен с 14 мая, цель <1.50, разрыв −1.07. Открыто: #217 (ядро nf4 не
обучается, delta_bpb=0.0), #230 (doctor-loop лежит, PAT истёк), #175 (застой
чемпиона).

## Порядок, если решено делать кодер

1. Влить `fix/509-qat-v2` — иначе артефакта не будет.
2. Собрать пары: `node scripts/harvest-igla-pairs.mjs` → 35 пар / ~346K токенов.
3. Прогнать кодогенератор по остальным спекам, чтобы довести до сотен пар.
4. LoRA поверх `Qwen3-1.7B` — **на арендованной GPU на часы**, не на Railway.
5. Railway оставить под HSLM и IGLA RACE, где CPU по делу.

## Чего не делать

- Не обещать дообучение LLM на Railway — там нет GPU.
- Не считать сырые `.t27` парным корпусом: 1.5М токенов языка ≠ данные «спек → код».
- Не запускать обучение до влития сохранения чекпоинта.
- Не оценивать думающую модель на CPU по скорости обычной генерации: множитель
  измерен и он почти сорокакратный по времени.

(Railway и render), `economical-testing` (цена проверок).
