## Core Database Tables

### 1. users
Main user table with Telegram user data:
```sql
CREATE TABLE users (
  id BIGSERIAL PRIMARY KEY,
  telegram_id BIGINT UNIQUE NOT NULL,
  username TEXT,
  first_name TEXT,
  last_name TEXT,
  bot_name TEXT,
  balance DECIMAL DEFAULT 0,
  limit INTEGER DEFAULT 0,
  count INTEGER DEFAULT 0,
  subscription TEXT,
  subscription_end TIMESTAMP,
  model TEXT,
  voice_id_elevenlabs TEXT,
  level INTEGER DEFAULT 1,
  email TEXT,
  company TEXT,
  position TEXT,
  designation TEXT,
  avatar_transform_used BOOLEAN DEFAULT false,
  aspect_ratio TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
)
```

**Common Queries:**
```typescript
// Get user by Telegram ID
const { data } = await supabase
  .from('users')
  .select('*')
  .eq('telegram_id', telegramId)
  .single()

// Update user balance
await supabase
  .from('users')
  .update({ balance: newBalance })
  .eq('telegram_id', telegramId)

// Create new user
await supabase
  .from('users')
  .insert({
    telegram_id,
    username,
    first_name,
    bot_name,
    balance: 0
  })
```

### 9. idempotency_keys
Prevent duplicate operations:
```sql
CREATE TABLE idempotency_keys (
  id SERIAL PRIMARY KEY,
  key TEXT UNIQUE NOT NULL,
  response JSONB,
  created_at TIMESTAMP DEFAULT NOW()
)
```

**Usage Pattern:**
```typescript
// Check if operation already processed
const { data } = await supabase
  .from('idempotency_keys')
  .select('response')
  .eq('key', idempotencyKey)
  .single()

if (data) {
  return data.response // Return cached response
}

// Process operation...

// Save result
await supabase.from('idempotency_keys').insert({
  key: idempotencyKey,
  response: result
})
```

## Row Level Security (RLS)

**Note**: This project uses Service Key, which bypasses RLS.

If implementing RLS:
```sql
-- Enable RLS
ALTER TABLE users ENABLE ROW LEVEL SECURITY;

-- Policy: Users can only see their own data
CREATE POLICY "Users can view own data"
  ON users FOR SELECT
  USING (telegram_id = auth.uid());

-- Policy: Users can update their own data
CREATE POLICY "Users can update own data"
  ON users FOR UPDATE
  USING (telegram_id = auth.uid());
```

## Query Optimization

### 1. Use Indexes
```sql
-- Common queries
CREATE INDEX idx_users_telegram_id ON users(telegram_id);
CREATE INDEX idx_assets_telegram_id ON assets(telegram_id);
CREATE INDEX idx_payments_telegram_id ON payments(telegram_id);
CREATE INDEX idx_payments_status ON payments(status);
```

### 2. Select Only Needed Fields
```typescript
// ❌ Bad: Select everything
const { data } = await supabase.from('users').select('*')

// ✅ Good: Select specific fields
const { data } = await supabase
  .from('users')
  .select('telegram_id, balance, subscription')
```

### 3. Use .single() for Single Row
```typescript
// ✅ Returns single object, not array
const { data } = await supabase
  .from('users')
  .select('*')
  .eq('telegram_id', telegramId)
  .single()
```

### 4. Batch Operations
```typescript
// ✅ Insert multiple records at once
await supabase.from('assets').insert([
  { telegram_id, video_url: url1 },
  { telegram_id, video_url: url2 },
  { telegram_id, video_url: url3 }
])
```

## Error Handling

### Standard Pattern
```typescript
try {
  const { data, error } = await supabase
    .from('users')
    .select('*')
    .eq('telegram_id', telegramId)
    .single()

  if (error) {
    console.error('Supabase error:', error)
    throw error
  }

  if (!data) {
    console.warn('User not found:', telegramId)
    return null
  }

  return data
} catch (error) {
  console.error('Database query failed:', error)
  throw error
}
```

### Common Errors
- `PGRST116` - Row not found (use .single())
- `23505` - Unique constraint violation
- `23503` - Foreign key constraint violation
- `42P01` - Table does not exist

## Best Practices

1. **Always handle errors** from Supabase queries
2. **Use TypeScript types** for database schemas
3. **Select only needed fields** for performance
4. **Use .single()** when expecting one row
5. **Implement idempotency** for critical operations
6. **Log database errors** for debugging
7. **Use transactions** for multi-step operations
8. **Cache frequently accessed data** when possible
9. **Monitor slow queries** via Supabase dashboard
10. **Keep migrations in version control**
