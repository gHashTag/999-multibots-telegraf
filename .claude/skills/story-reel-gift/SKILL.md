# Рилс-подарок клиенту (лид-магнит №2)

Решение владельца 26.09.2026: «надо делать для каждого клиента из его данных,
как например у 2086031075 @Ryabinika_Perm — изучи и сделай её рилс с её
данными и создай шаблон… про её бизнес, чтобы она отправить могла в
инстаграм, с её фото, и голос используй из переписки».

Первый подарок — портрет 9:16 из аватарки (`crm_deliver_photo`). Второй —
этот рилс. Смысл второго: человек получает готовый ролик про СВОЁ дело своим
голосом, выкладывает его и приходит за следующими — это вовлечение в бота.

## Когда

- Портрет уже подарен: `crm_lead_context` → `portrait.first` говорит
  «второй подарок: рилс-история…», `portrait.reelGiven` — был ли рилс.
- Человек сам говорил о продвижении, подписчиках, рассказе о деле (сигналы,
  цель в `crm_client_plan`).
- Не тем, кто попросил выключить ассистента: `crm_voice_clone` и отправка
  откажут сами (`assistant-opt-out.ts`).

## Из чего (всё — его данные, ничего не выдумывать)

| что                | откуда                                                                         |
| ------------------ | ------------------------------------------------------------------------------ |
| лицо               | `crm_client_face {lead_id}` — аватарка или присланное им фото                  |
| дело, город, слова | `crm_lead_context {chat}` (переписка, память), `crm_client_plan {telegram_id}` |
| голос              | `crm_voice_clone {chat}` — только ЕГО голосовые из лички с владельцем          |
| призыв             | его дело: «Заказ — в директ», «Запись — ссылка в профиле»                      |

## Рецепт — постоянный шаблон `story_reel` (с 26.09.2026)

«Сохрани шаблон для постоянной работы! Только в конце паузу добавь для CTA»
(владелец). Цепочка больше не собирается руками по шагам — это ОДИН вызов:

1. **Голос клиента** — `crm_voice_clone {chat}` один раз на человека.
2. **Весь рилс** — `story_reel`:
   ```
   story_reel {
     image_url: <его фото: crm_client_face>,
     scenes: [ {setting, line} ×3 ],   // обстановка новая в каждой, реплики 2–4 с
     style:  <один стиль на все кадры>,
     for_lead: <его id>,               // говорит ЕГО голосом
     cta:    <призыв его дела>,         // стоит на экране в паузе
     pause_sec: 3                       // по умолчанию, 1–4
   }
   ```
   Внутри: кадры (все сразу, из одного фото) → голос → липсинк → StoryReel.
   В конце — **пауза 3 с**: последний кадр стоит, надпись `cta` появляется за
   0,2 с и держится всю паузу. Было 2 с с проявлением 0,33 с — прочитать
   успевали меньше двух секунд.
   Реплики: кто и где → что делаю → как заказать. Названия, аббревиатуры и
   цифры — словами, как их говорят («Тринити», а не «S³AI DNA»).
3. **Не вышло целиком** (кадр ещё рисуется, деплой оборвал, липсинк упал) —
   ответ несёт `stills` и `clips`; повтори `story_reel` с ними: готовое не
   делается и не оплачивается второй раз. Если кадр ещё рисуется — голос и
   липсинк не начинаются вовсе.
4. **Отдать** — `tg_send_video {chat, url, caption, gift: true}`: карточка
   владельцу, уходит только по его кнопке. Подпись: «это вам — рилс про ваше
   дело вашим голосом, можно сразу в Instagram» + один мягкий вопрос.
   `gift: true` пишет в журнал `подарок в личке: video: …` — так `portraitOf`
   отличает рилс от портрета.

Тот же инструмент — рилс самого владельца: `image_url` — его эталон
`https://app.t27.ai/brand/owner-noir-portrait.jpg`, `style` — нуар и значок
▽ словами, без `for_lead` (дом говорит клоном владельца).

**Кадр, который рисуется дольше ~3 мин, не потерян.** Замер 26.09.2026 для
Лены: `image_edit` (nano-banana) ответил без ссылки на кадрах 1 и 2 — ждал
3 мин и вернул «ещё рисуется», а сами файлы легли в «мои файлы» через ~20 с
(`my_assets`). Не перерисовывать (это вторая оплата), а взять последние
`agent-edit` из `my_assets` по порядку вызовов. Каждый кадр — 1,5–3 мин.

Карточки делает только поверхность, где владелец может нажать (бот,
приложение). Из `/mcp` или A2A карточка не встаёт в очередь — рилс тогда
отдаётся владельцу, а отправка клиенту — его словами в боте.

## Голос клиента: правила и цена

- Источник — только голосовые, которые ОН прислал владельцу в личку. Инструмент
  сам их скачивает через сессию владельца и выкидывает голосовые владельца из
  того же чата: клон смеси — ничей голос. Ссылки на чужое аудио нет нарочно.
- Клон принадлежит паре (владелец, клиент), таблица `lead_voices`. Говорить
  им может только этот владелец и только `for_lead`.
- В маршрут клон идёт полем `clone_voice`, которое маршрут принимает только от
  самого сервиса; `voice_id` — только библиотечный голос. До 26.09.2026 клон
  владельца шёл в `voice_id`, и любой агент мог написать его id и говорить
  голосом владельца — закрыто (`minimax-voices.ts`, `isCloneVoiceId`).
- Replicate `minimax/voice-cloning`: **$3 за клон** (страница модели,
  26.09.2026: «around 33 outputs for $100»), от 5 с звука, «чем больше, тем
  точнее». Наша цена — 1200 ток. (×2 наценка / $0,005). Клон делается под
  `speech-02-turbo` — ту модель, которой говорит наша нога озвучки.
- Голосовые Telegram — OGG/Opus; склеиваются и перекодируются в MP3 (моно,
  44,1 кГц, до 180 с) перед клоном.

## Шаблон в CRM: любой клиент с голосом и фото, любая тема (с 26.09.2026)

Решение владельца: «создай в CRM это как шаблон для клиентов, кто сдал голос и
фото из аватарки, для любой истории» и «чтобы она могла новый получить одним
нажатием».

Один движок (`render/src/agent/story-template.ts`), три двери:

| Кто просит                                | Дверь                                                                                                                                               | Кто платит                                           | Куда приходит                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| продавец из карточки клиента в приложении | панель «🎬 Рилс-история» (`StoryReelPanel`)                                                                                                         | продавец («дом» — 0)                                 | продавцу в бот: проверить и переслать самому |
| агент продавца                            | `crm_story_reel {lead, start:true, topic}`                                                                                                          | продавец                                             | продавцу                                     |
| сам клиент                                | `t.me/<бот>?start=reel` → `POST /api/story/next`                                                                                                    | клиент (VIP: `story_reel.payer: 'owner'` — продавец) | клиенту в тот же бот + кнопка «🎬 Ещё рилс»  |
| сам клиент, своя страница                 | «🎬 Мои рилсы» `t.me/<бот>?start=app_story` → `/story` (`my_story_reel`): лицо, голос, следующая тема плана, ЦЕНА ДО НАЖАТИЯ, любая тема, его рилсы | клиент (или подарок)                                 | клиенту в его бот                            |

- **Кто подходит:** есть лицо (`crm_people.avatar_url`, его заполняет
  `crm_client_face`; панель сама смотрит аватарку, если CRM ещё не смотрела)
  и клон голоса (`lead_voices`, `crm_voice_clone`) — либо, когда жмёт
  продавец, хотя бы 5 с её голосовых в личке (ниже, «две дороги»). Больше
  ничего не нужно. Клон — на продавца: у другого продавца голоса этого
  человека нет. `crm_story_reel {lead}` без `start` отвечает `voice_mode`
  (`clone` / `notes`) и `price_tokens` — назвать до траты.
- **Любая тема:** та, что написали; пусто — следующий пункт его контент-плана
  (`idea` → `doing` одним запросом); плана нет — сценарист сам берёт новую
  тему про его дело и знает, какие уже были.
- **Профиль VIP** (`crm_client_profiles.profile.story_reel`): `face_url`,
  `style`, `cta`, `pause_sec`, `payer`, `done` (темы, уже сделанные руками).
  Без профиля — спокойный тёплый стиль и призыв «Напишите мне».
- **Переживает передеплой:** задача — строка `story_jobs`, готовые кадры и
  клипы пишутся сразу; пульс каждые 30 с; задачу, чей процесс умер (тишина
  100 с), подхватывает уборка (каждые 2 мин) — одна на задачу, даже когда два
  экземпляра рендера живы одновременно. Оплаченное второй раз не делается.
- **Провал** возвращает пункт плана в `idea` и говорит причину словами.

## В пайплайне, не скриптом (решение владельца 27.09.2026)

«Надо встроить в пайплайн, а не скриптами вручную делать!!» Рилс клиенту
делает ЗАДАЧА `story_jobs`, а не функция Railway и не долгий вызов
`story_reel` внутри одного хода агента (передеплой рвал такой вызов, а
продолжение зависело от того, повторит ли модель stills/clips).

```
crm_story_reel {lead, start: true,
  scenes: [{setting, line}, …],   // свой сценарий — делается ровно он, без сценариста
  style, cta,                      // свой свет и призыв поверх профиля
  end_card: {bg, title, text, accent, button},  // палитра концовки, #hex (v7)
  to: "dm" | "<chat_id группы>" | "none",   // пусто — привязанная группа клиента
  caption}                         // подпись; пусто — готовая с его страницей «Мои рилсы»
```

- **Готовый приходит продавцу КАРТОЧКОЙ** (`story-card.ts`): рилс, куда
  уйдёт (группа — «увидят все участники»; личка — подарок), подпись и те же
  две кнопки, что у любой карточки (`tgp:ok` / `tgp:no`). Нажатие отправляет
  от его аккаунта обычной дорогой `tg_send_video` → `/api/tg/proposal/confirm`.
  Без нажатия ничего не уходит.
- **Чужую карточку не вытесняет.** У человека одна нажимаемая карточка;
  пока ждёт другая (в ней может быть уже оплаченный портрет), рилс говорит
  «карточка придёт сюда», а уборка предлагает её, когда очередь свободна.
- **Группа** привязывается тем же `to: "<chat_id>"` — только группа, которую
  CRM уже прочла (`crm_groups`); иначе отказ ДО траты.
- **Лента.** Рендер агента больше не публикуется в ленту сам (#3081): он
  ждёт одобрения в «Ждут одобрения» того, кто платил.
- **Голос клиента — две дороги (спека v4, 27.09.2026).** Владелец: «у нас
  Kie оплачен!!» — не отправлять его пополнять Replicate.
  1. **Клон** (Replicate MiniMax, `crm_voice_clone`): новые слова её голосом.
     У KIE клонирования нет; Replicate без денег отвечает 402.
  2. **Её голосовые, без клона** (`story-voice-notes.ts`): когда жмёт
     ПРОДАВЕЦ, а клона нет, шаблон сам берёт её НАСТОЯЩИЕ голосовые из лички
     с продавцом (не из группы), склеивает до 12 с (нужно от 5), режет по
     паузам (`silencedetect`, ближайшая пауза в пределах 1,5 с от ровного
     разреза, кусок не короче 1,5 с) — кусок на сцену — и делает липсинк на
     Kie её же звуком. Ни клона, ни Replicate, ни синтеза; слова — те, что
     она сама сказала. Куски приходят в `story_reel` только из задачи
     (`ctx.storyVoices`), не из аргументов модели.
  - **Клон есть, но Replicate отказал (402), спека v5.** Рилс продавца в том
    же прогоне переходит на её голосовые, на уже оплаченных кадрах; только
    при отказе провайдера (401/402/403/429, баланс, ключ), не при плохой
    реплике. Замер 27.09: у Гайи и Фариши клоны ЕСТЬ — без v5 шаблон шёл бы
    в клон и упирался в 402.
  - **Суточный лимит генераций считается ДО траты (спека v6).** Рилсу
    нужно: недостающие кадры + (реплики клона) + недостающие липсинки +
    сборка (клон 3 сцены — 10, голосовые — 7). Не хватает — отказ словами
    до первого кадра. Упёрлась в лимит на полпути — задача ЖДЁТ окна,
    попытка возвращается, продавцу говорится один раз. Замер 27.09:
    Фариша — кадры и голос оплачены, липсинк упёрся в 60/сутки, три
    попытки сгорели за 6 минут. Сам лимит (60) — предохранитель владельца,
    не поднимать без него.
  - **Концовка в её визуале — и от продавца (спека v7).** Нет палитры в
    профиле (Гайя) — продавец даёт `end_card`: поле продавца поверх поля
    профиля, профиль поверх умолчания композиции; палитра продавца хранится
    в задаче (`story_jobs.end_card`) — продолжение после передеплоя рисует
    ту же концовку. Цвет — #hex из 3/4/6/8 цифр; `black` не молча
    выбрасывается, а называется продавцу. Призыв (цвет `title`) и строка
    кнопки (`accent`) против фона — не меньше 4,5:1 (WCAG): нечитаемую
    палитру продавца отказ ДО траты; палитру профиля — только
    предупреждение (`end_card_why` в ответе без start), рилс как был.
    Проверить палитру бесплатно: `crm_story_reel {lead, end_card}` без start.
  - Сам клиент (`start=reel`, «Мои рилсы») без клона — по-прежнему отказ:
    её голосовые без продавца не читаются.
  - Чужим голосом не озвучивать никогда.

## Числа живут в спеке t27, не здесь (с 27.09.2026)

Спека записи — `gHashTag/t27` `specs/automation/crm-story-reel.t27`
(t27#4849, t27#4850). В рендер она положена как есть в
`apps/vibee-editor/render/src/spec/` вместе с выводом `t27c gen-ts`, и код
(`story-template.ts`, `story-reel-tool.ts`, `story-card.ts`) ИМПОРТИРУЕТ
оттуда числа: лимиты, тайминги задачи, цены, правила карточки.
`src/spec/crm-story-reel.test.ts` падает, если сгенерированный модуль
разошёлся со спекой, если код написал число сам, или если хост перестал
делать то, что говорят тесты спеки.

Поменять число — только в спеке, затем:

```
cargo build --release -p t27c           # в клоне t27 (~4 мин)
pip download --no-deps ziglang==0.16.0  # test-report гоняет тесты через Zig 0.16
t27c test-report specs/automation/crm-story-reel.t27   # тесты спеки по-настоящему
node apps/vibee-editor/render/scripts/sync-t27-spec.mjs <t27> automation/crm-story-reel
```

`t27c test` только СЧИТАЕТ тесты; выполняет их `test-report`. Проверка
«может ли упасть»: сломать один assert — должен быть FAIL.
