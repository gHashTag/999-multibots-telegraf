# Вход в приложение

Собрано 07.09.2026, после ночи, в которой вход ломался трижды — и два раза
это сделал я сам. Здесь то, что нужно знать ДО правки, и то, чем проверять.

## 1. Четыре двери, и кто в какую ходит

| дверь                                  | кто ею пользуется                      | чем представляется              |
| -------------------------------------- | -------------------------------------- | ------------------------------- |
| `POST /api/auth/telegram`              | мини-апп при запуске (обмен на сессию) | `init_data` в теле              |
| `POST /api/auth/widget`                | веб вне Telegram (кнопка Login Widget) | подписанный объект виджета      |
| `POST /api/auth/pair/start` → `/claim` | **приложение на iPhone**               | код из 8 цифр, набранный руками |
| `POST /api/auth/refresh`               | все, у кого есть сессия                | refresh-токен                   |

**Как войти на телефоне (то, что спрашивают чаще всего):**

1. В Telegram боту — команда `/app`.
2. Кнопка «🔑 Войти в приложение» открывает мини-апп сразу на экране кода
   (`/pair` — если открылась лента или дорога приветствия, сломан диплинк).

   Адрес переезжал дважды, и оба раза после поломки у живого человека:
   `/profile` высаживал на «Шаблоны» (07.09.2026), `/profile?tab=agent`
   перестал существовать 17.09.2026 — профиль ушёл под дорогу приветствия,
   третья карточка которой просит 10 000 звёзд, и человек, УЖЕ ОПЛАТИВШИЙ
   подписку, увидел по этой кнопке счёт. Сервер такого условия не ставил
   никогда: `/api/auth/pair/start` смотрит подпись запуска и дату выхода, и
   больше ничего. Поэтому у экрана теперь свой адрес (`player/src/pages/Pair.tsx`),
   а правило «пока не оплачено — профиль не открывается» (`profileGate.ts`)
   не тронуто.

3. Нажать «Показать код для входа» — появятся **8 цифр**, живут **2 минуты**,
   одноразовые.
4. На телефоне: Профиль → «Войти» → набрать код.
5. В Telegram придёт уведомление «🔐 Вход в приложение выполнен» с именем
   устройства и временем. **Не пришло — вход не состоялся.**

## 2. Главное правило: ОДНО удостоверение за раз

`authenticate()` в `apps/vibee-editor/render/auth.ts` перебирает ветки
**по порядку**:

```
ключ сервера (X-Api-Key) → ключ агента (X-Agent-Key) → СЕССИЯ (Bearer) → подпись (initData)
```

и — вот это дороже всего —

> **отказ НЕ проваливается в следующую ветку.**

Присланный `Bearer` РЕШАЕТ исход. Протух — 401, и подпись не смотрят.

Отсюда правило клиента:

> **Пока есть подпись `initData`, идёт ОНА ОДНА.** Сессия — для тех, у кого
> подписи нет (веб, iOS).

07.09.2026 я нарушил это правило, написав в обосновании «сервер примет любое
из двух». Access живёт **600 секунд** — через десять минут после запуска
мини-апп слал протухший `Bearer` вместе с исправной подписью и получал 401 на
каждый запрос. Снаружи: «не входит автоматом, как раньше».

Сторож на этот стык: `credential-precedence-contract.test.ts`. Он падает и
когда клиент снова шлёт два заголовка, и когда на сервере переставили ветки.

## 3. Величины живут на сервере. Клиент их НЕ повторяет

| величина                        | где                | почему нельзя копировать                                                            |
| ------------------------------- | ------------------ | ----------------------------------------------------------------------------------- |
| `PAIRING.DIGITS = 8`            | `session-store.ts` | копия `== 6` в iOS **сделала вход невозможным**: поле обрезало ввод на шестой цифре |
| `PAIRING.TTL_SECONDS = 120`     | там же             | текст «действует 2 минуты» — такая же копия                                         |
| `ACCESS_TTL_SECONDS = 600`      | `session.ts`       | из-за него «работало 10 минут, потом перестало»                                     |
| `REFRESH_TTL_SECONDS` = 60 дней | там же             |                                                                                     |

Клиент принимает **диапазон** и отдаёт решение серверу; тексты берут число
**из самих данных** или не называют его вовсе. Сторож:
`code-length-agreement.test.ts`.

## 4. Чем проверять (по возрастанию цены)

```bash
tri entry      # что отвечают четыре двери на мусор + тормоза + длина кода
tri session    # сроки, окно гонки, как три клиента отвечают на 409
tri pairing    # длина кода: сервер против клиентов
tri shipped    # что уехало в прод И пользуется ли этим кто-нибудь
tri tma        # адреса, чтобы ПОСМОТРЕТЬ экраны входа локально
```

`tri tma` печатает адреса с подставкой для разработки
(`?mock-telegram=<id>&mock-pair-code=12345678`). Она вырезается из ЛЮБОЙ
сборки плагином Vite — иначе экраны входа вне Telegram посмотреть нельзя
вообще, и правки идут вслепую. Так дважды ломался iOS.

## 5. «Не входит» — что смотреть по порядку

1. **Работало и перестало само?** Ищи СРОК ЖИЗНИ: access 10 минут, initData
   24 часа, код 2 минуты. Почти всегда дело в нём.
2. **`tri entry`** — двери отвечают внятно? 401 с причиной ≠ 500.
3. **Клиент шлёт два удостоверения?** `tri tma`, и посмотреть `authHeaders`
   в `apps/vibee-editor/player/src/lib/apiFetch.ts`.
4. **Уехало ли исправление в прод?** `tri shipped` — «уехало» и
   «пользуются» это разные вопросы.
5. **Профиль пишет «подпись не пришла»?** Причина может быть другой: у
   аккаунта нет @имени. Профиль открывается по `/:username`, и при отсутствии
   имени сервер спрашивается по `telegram_id`.

## 6. Чего делать НЕЛЬЗЯ

- **Слать `Bearer` вместе с `initData`** — см. §2.
- **Писать в комментарии утверждение о чужом коде, не открыв его.** Именно так
  я сломал вход: обоснование в комментарии ощущается как проверка, ею не
  являясь. Утверждение о поведении сервера — только с цитатой или тестом.
- **Копировать серверные величины в клиент** — см. §3.
- **Ставить `await` на уведомление о входе.** Вход уже состоялся; ожидание
  чужой сети превратит недоступный Telegram в сломанный вход.
- **Показывать «Выйти» внутри Telegram.** Личность даёт сам запуск, автологин
  вернёт человека через доли секунды — кнопка оставляет экран в противоречии.
