# /tri — человек ↔ человек, агенты между ними в помощь

Имя дал владелец 20.09.2026: **tri** — это команда, где на концах два живых
человека, а агенты стоят между ними и помогают. Не агенты вместо людей.

Подробный разбор ловушек — в скиле **`rainbow-bridge`**. Здесь только порядок
прогона и роли; правило живёт в одном месте.

## Три роли (слова владельца, 21.09.2026)

> «один делает запрос на функцию, второй её предоставляет, третий смотрит
> целостность ответа на вопрос и корректирует в случае проблемы»

| Роль            | Кто                                      | Что делает                                          |
| --------------- | ---------------------------------------- | --------------------------------------------------- |
| **Просящий**    | аккаунт стороны A (юзер-бот)             | шлёт команду / вопрос / файл боту фермы             |
| **Исполняющий** | бот фермы и агент рендера                | отвечает, как ответил бы живому человеку            |
| **Судья**       | агент, читающий переписку (`tg_history`) | сверяет ответ с вопросом, при сбое — в улей и чинит |

## Порядок прогона

```bash
tri bridge 144022504 435572800   # 1. машина: боты, профили обеих сторон, агент на двух поверхностях
tri commands                     # 2. какие команды меню ещё НИКТО не нажимал
```

1. **`tri bridge`** — минута, параллельно, никому не пишет. Смотреть только
   жёлтые и красные строки. Раздел «профили» говорит, готова ли сторона к
   **реальной работе**: продавец ли она (подключён ли Telegram), читается ли
   живой кошелёк, знает ли её рендер. У каждого пробела — чьё нажатие его
   закрывает. Код входа вводит сам человек; начислять токены решает владелец.
2. **`tri commands`** — по переписке владельца с каждым ботом: ✓ ответил,
   ✗ молчит, · не пробовали. Строки «·» — список нажатий для людей.
3. **Люди** проходят только то, что машина не может: настоящее голосовое в обе
   стороны, настоящий `.md` и `.pdf`, оплату через свою кассу, мини-апп со
   своего аккаунта.
4. **Судья**: после нажатий — снова `tri commands`; красное уходит в улей
   (`bot-errors`, `client-unanswered` пишутся сами).

## Чего /tri НЕ делает (и почему)

- **Не пишет от чужого имени.** Аккаунт @playom — живой человек, жена
  владельца. Агент действует **от** владельца и **никогда** от лица второй
  стороны.
- **Не шлёт от аккаунта владельца без его нажатия.** Каждая отправка с его
  аккаунта — предложение с кнопкой «Отправить». Режим, в котором юзер-бот
  владельца сам переписывается с ботами фермы, возможен только как отдельное
  разрешение владельца: один прогон = одна карточка = одно нажатие, адресаты —
  **только боты фермы** (список из `getMe` по `BOT_TOKEN_*`), не люди.
  Пока такого разрешения нет, «просящий» — это человек с телефоном.

## Проверка перед тем, как сказать «работает»

«Работает» — это когда живой человек с телефона получил правильный ответ, а не
когда тест зелёный. Доказательство — строка ✓ в `tri commands` или цитата из
`tg_history`, а не вывод `vitest`.
