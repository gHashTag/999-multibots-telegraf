# Admin chat

## When to Use This Skill

- Нужно отправить ошибку или служебное сообщение админам.
- «Ошибка случилась, а в рабочем чате тишина» / «оплата упала, никто не узнал».
- Пишется новый код, который что-то сообщает команде.
- Меняется `ADMIN_CHAT_ID`, `adminChatId.ts`, `errorMessageAdmin`, `sendServiceErrorToAdmin`.

## Что это за чат

**Владелец, 2026-10-08:** «@t27_ai — это наш рабочий чат, бот там админ. Разработку
бота искать там. ВСЕ ошибки и информационные сообщения для админов слать туда.»

- Адрес: `@t27_ai`. Владелец назвал также id `3854462316`.
- Здесь — разработка бота: обсуждение, служебные сообщения, ошибки.
- Бот должен быть участником (лучше админом) чата — иначе Telegram откажет.

## Единственный путь: один резолвер

Адрес канала админов — переменная **`ADMIN_CHAT_ID`** сервиса `999-multibots-telegraf`
(Railway). Читает её ТОЛЬКО `resolveAdminChatId()` в `src/helpers/adminChatId.ts`
(добавляет `@` к голому имени, убирает пробелы, `null` если не задано).

| Откуда шлём                | Как                                                                |
| -------------------------- | ------------------------------------------------------------------ |
| есть `ctx` (обработчик)    | `ctx.telegram.sendMessage(resolveAdminChatId(), …)`                |
| нет `ctx` (Inngest и т.п.) | `sendToAdminChat(text)` — `src/helpers/error/sendToAdminChat.ts`   |
| ошибка в сервисе           | `errorMessageAdmin(ctx \| null, error)`, `sendServiceErrorToAdmin` |

## Законы (не нарушать)

1. **Никогда не зашивать адрес в код.** Ни `'@какой_то_чат'`, ни `process.env.ADMIN_CHAT_ID`
   напрямую. Прежде два хелпера ошибок слали в зашитый `'@neuro_coder_privat'`, который
   никто не читал (исправлено 2026-10-08).
2. **`null` ctx — не повод молчать.** `errorMessageAdmin(null, err)` раньше делал
   `console.error` и выходил: упавшая оплата (Inngest `paymentProcessing`, `modelTrainingV2`)
   не доходила ни до одного админа. Теперь уходит через `sendToAdminChat`.
3. **`fetch` проверяет `resp.ok`.** `fetch` не бросает на 400 — без проверки отказ выглядит
   доставкой. `sendToAdminChat` проверяет и пишет в лог настоящий ответ Telegram.
4. **Уведомление о сбое не должно стать вторым сбоем.** Отправители не бросают исключений.
5. Значение токена бота не логируется никогда.

## Переключить канал на @t27_ai (шаг владельца)

Код уже шлёт ВСЁ туда, куда указывает `ADMIN_CHAT_ID`. Чтобы это был `@t27_ai`, владелец
задаёт переменную в Railway. **Сначала проверить адрес** — неверное значение молча глушит
ВСЕ уведомления админам (именно этот дефект резолвер и закрывает):

```bash
# Хост Bot API — по токену: бот может жить на нашем сервере, а не в облаке
# (services/telegramApi.ts). Значения токена не печатать.
KV=$(railway variables --service 999-multibots-telegraf --kv)
TOKEN=$(printf '%s\n' "$KV" | grep '^BOT_TOKEN_1=' | cut -d= -f2-)
ROOT=$(printf '%s\n' "$KV" | BOT_API_TOKEN="$TOKEN" node scripts/lib/telegram-api.cjs api-root --env-from-stdin)
curl -s "$ROOT/bot$TOKEN/getChat?chat_id=@t27_ai" | head -c 200   # "ok":true → адрес верный
railway variables --service 999-multibots-telegraf --set ADMIN_CHAT_ID=t27_ai   # резолвер сам добавит @
```

Про id: `3854462316` положительный — так выглядит id пользователя/бота; id группы
отрицательный (`-100…`). Если `@t27_ai` — публичный чат, надёжнее задать имя (`t27_ai`).
До 2026-10-08 в проде стоял `neuro_blogger_pulse` (→ `@neuro_blogger_pulse`, `-1002298297094`).
