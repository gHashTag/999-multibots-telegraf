# Воркфлоу цикла opus-improvements

Процедура ОДНОЙ итерации. Крон срабатывает каждые 15 минут и подаёт один и тот
же промпт, поэтому вся преемственность держится на файлах, а не на памяти:
между срабатываниями контекста нет.

Читать сверху вниз. Шаги 0–2 обязательны всегда, даже если кажется, что
«ничего не изменилось».

---

## 0. Взять лок и осмотреться

```bash
.claude/loop-opus/guard.sh || exit 0
```

Выход 1 — итерацию НЕ выполнять. Это не ошибка, это штатный отказ: предыдущая
ещё идёт.

Страж заодно печатает, на какой ветке рабочее дерево и когда коммитил второй
агент. Если его последний коммит младше минуты — он в работе прямо сейчас,
рабочее дерево трогать нельзя.

## 1. Прочитать состояние

```bash
cat .claude/loop-opus/STATE.json
```

`backlog` — что делать. `blocked` — чего НЕ пытаться (там записано, почему).
`measured` — что уже замерено; повторный замер того же без причины это трата
такта.

**Правило преемственности:** новая итерация не отменяет решений прошлой. Если
считаешь прошлое решение неверным — сначала запиши в `selfCritique`, ЧЕМ оно
неверно, и только потом меняй. Молчаливый откат чужой (и своей прошлой) работы
— главный способ, которым непрерывный цикл съедает сам себя.

## 2. Развязка с чужим агентом

В репозитории параллельно работает второй автономный агент: ветка
`loop/agent-improvements`, каталог `loop/`, коммиты каждые 40–70 секунд.

- Никогда не коммитить в его ветку и не писать в `loop/`.
- Никогда не `git stash` — там его незакоммиченные файлы.
- Никогда `git add -A` и `git add .` — только явные пути.
- Работать в **отдельном worktree**:

```bash
git worktree add <scratchpad>/wt-opus -b loop/opus-<тема> origin/main
ln -sfn <главный репо>/apps/vibee-editor/player/node_modules \
        <scratchpad>/wt-opus/apps/vibee-editor/player/node_modules
```

Симлинк зависимостей обязателен: в свежем worktree их нет, а ставить заново —
это гигабайт и несколько минут.

## 3. Измерить, а не предположить

Главное правило цикла: **находка без числа — не находка.**

Что считается замером:
- `getBoundingClientRect` / DOM в живом приложении;
- `curl` с `%{time_total}` по проду, минимум 3 повтора;
- запрос к базе с `count(*)`, а не выборка «посмотреть»;
- кадр из готового mp4, а не рассуждение о композиции.

Что НЕ считается замером: чтение кода, «выглядит правильно», зелёная сборка.

Прежде чем править компонент — доказать, что он рендерится: грепнуть импорт
вне его собственной папки И увидеть элемент в живом DOM. В этом репозитории
мёртвого кода, выглядящего живым, больше, чем ожидаешь.

## 4. Одна правка — один PR

Мелкий PR с обоснованием-замером лучше крупного с рассуждением.

В описании PR обязательны две вещи:
1. таблица «было → стало» с числами;
2. раздел **«чего НЕ проверял»**.

Второй важнее первого. Отчёт без границ применимости читается как гарантия,
которой не давали.

## 5. Проверить, что не сломал прошлое

```bash
# типы — с --pretty false, иначе grep по цветному выводу молча врёт
npx tsc --noEmit --pretty false | grep -c "error TS"
```

Сравнивать ВСТЫК: счёт до правки и после, в одном прогоне подряд. Число
ошибок «примерно как раньше» — не измерение.

Для тестов сравнивать МНОЖЕСТВА имён прошедших тестов, а не их количество:
счётчик может вырасти в тот же момент, когда сломана проверка.

## 6. Обновить дашборд и состояние

```
.claude/loop-opus/dashboard.html   →   Artifact (тот же путь = тот же URL)
.claude/loop-opus/STATE.json       →   iteration++, measured, shipped, blocked
```

В дашборде обязателен блок **«самокритика»**: что в этой итерации сделано
хуже, чем выглядит. Итерация без самокритики — почти всегда итерация, в
которой не посмотрели.

## 7. Записать опыт

Урок, который не превратился в тест, инструмент или строчку скилла, между
итерациями не переживёт: контекста нет. Правило без проверки — украшение.

## 8. Проверить, что правка ДОЖИЛА до main

```bash
node .claude/loop-opus/verify-landed.mjs
```

Выход 1 — правку перезаписали. Так уже было: PR #668 влили, через шесть минут
влился PR второго агента, отведённый от main ДО того и тронувший тот же файл.
Его версия победила. `git log` при этом показывал оба коммита, а
`merge-base --is-ancestor` отвечал ДА.

**Коммит в истории ≠ правка в файле.** Изоляция через worktree защищает
рабочее дерево, но не порядок мержей.

Добавляя новую правку — впиши её след в `landed.json`: путь и строку, которая
обязана быть в файле. Строку, а не коммит.

Восстанавливать — `cherry-pick` поверх текущего main, НЕ откатом чужого: чужая
правка в том же файле обычно цела и к пропаже отношения не имеет.

## Чего этот цикл не делает

- Мержит свои PR сам — но только проверенные ЗАМЕРОМ, а не зелёной сборкой.
  До итерации 08 действовало обратное правило, и очередь из шести PR сама
  стала риском: CI репозитория мёртв с 2 июня (биллинг GitHub), зелёного
  статуса не существует, и ждать его бессмысленно.
- Не трогает данные в проде без отдельной команды.
- Не удаляет чужие файлы, ветки и незакоммиченную работу.
- Не выдаёт непроверенное за проверенное. Если инструмент сломан — так и
  пишет, и кладёт задачу в `blocked`, а не заполняет пробел правдоподобным
  текстом.
