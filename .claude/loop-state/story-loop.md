## Правила витка (не ломать прошлую работу)

1. Сначала `tri loop`: что в работе, что не сделано. Пункт `[~]` — начат
   прошлым витком: доделать или откатить, а не начинать заново рядом.
2. Не вливать в рендер, пока идёт задача рилса — деплой её прервёт.
   Проверка (с витка 3): логи рендера, фильтр `"[story] job"` — попытка
   с «started» без «ended» ещё идёт. ДО витка 3 у задачи не было ни одной
   строки в логах, и «нет строк [story]» не доказывало ничего (я на это
   опирался в витке 2). `npm error signal SIGTERM` через ~40 с после
   нового старта — штатная остановка старого контейнера, не падение.
   С витка 6 — `tri busy`: окно логов БЕЗ фильтра (15+ минут; JSON из
   Railway MCP get-logs или `railway logs`) на stdin; пары started/ended
   задач рилса и `[agent:turn]` хода агента; код 1 — идёт, сливать рано;
   CUT — оборвано прошлым деплоем и не подхвачено. Выборка MCP по сервису
   НЕПОЛНА поперёк деплоев (виток 7: окно вернуло старты, через 15 минут —
   пусто; концы ходов в первой выборке отсутствовали) — брать окно ТЕКУЩЕГО
   деплоя (deploymentId) с его старта. Пустой ввод — код 2
   («нет данных» ≠ «простаивает»). Виток 6 проверял на глаз: ход
   владельца шёл 193 с поперёк проверки.
3. Предохранители владельца (суточный лимит 60 генераций, заморозка Гайи,
   карточка перед отправкой клиенту) не ослаблять без его слова.
4. Каждая правка вертикали с числами — спека t27 первой (навык t27-spec-first).
5. Полный прогон рендера и мутации перед слиянием; GitHub Actions стоят
   (биллинг) — локальные ворота и комментарий в PR.
6. Окружение: корневой vitest 5 и `react` в корне (`npm install --no-save
react@18.3.1 react-dom@18.3.1`) — иначе pre-push ложно краснеет.
7. Не мутировать файлы, пока идёт полный прогон (он читает их же).
   И сам `bin/tri` тоже (виток 7: правка справки посреди `tri full-run` —
   «unexpected EOF» после прогона). С витка 7 tri — одна группа `{ … };
exit "$?"` и читается целиком до запуска; `exit` на ТОЙ ЖЕ строке, иначе
   bash дочитывает правленый файл после группы (проверено на копии).
   Код выхода конвейера — код последнего звена: `tri full-run | tail`
   вернул 0 при RED. Вердикт — строка `== render: green/RED`, или без трубы.
   `pkill -f "<команда>"` убивает и свою оболочку, если образец есть в её
   строке — искать pid через `ps | grep [x]`.
8. Слияние squash — с явными `commit_title`/`commit_message`.
9. Полный прогон — `tri full-run [render|player|both]` (с витка 5): путь,
   итоги, падения; красно, если прогон шёл не в том пакете. Руками —
   всегда с путём: `grep -E "RUN |Test Files|Tests |FAIL"`.
   Виток 4: фоновый «полный прогон рендера» отчитался 178 файлами — это был
   плеер; рендер — 410. Без строки RUN подмена не видна.
